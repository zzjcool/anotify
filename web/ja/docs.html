Agent 連携

Anotify の中核シナリオ：<b class="text-zinc-200">Agent がタスクを完了すると、通知がすべてのデバイスに自動的にプッシュされます</b>。連携は 2 ステップ — 上報用 Key を作成し、タスク終了時に POST リクエストを送るだけです。

1 上報用 Key を作成

<a href="keys.html" class="text-indigo-300 underline decoration-indigo-400/30 underline-offset-2 hover:text-indigo-200">API Keys</a> ページで <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">notify:send</code> 権限の Key を新規作成してください（プレフィックス <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">ant_live_</code>）。作成後すぐに保存してください。

2 タスク終了時に上報

Agent の終了イベント（例：pi の <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">agent_settled</code>）またはスクリプトの末尾で、Key を添えて <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">POST /v1/notify</code> を送信します。

最小構成 · curl 一行で全デバイスに通知
curl -X POST https://あなたのドメイン/v1/notify \ -H "Authorization: Bearer ant_live_9f3a2c8e…" \ -H "Content-Type: application/json" \ -d '{"title":"デプロイ完了","status":"success","body":"ビルド成功、本番環境にデプロイ済み"}'
通知の旅 
 Agent(pi)              Anotify              WebPush svc              Device(iOS/Mac)
    │                        │                        │                        │
    │ ① agent_settled        │                        │                        │
    │ ② POST /v1/notify ────▶│ ③ verify Key → locate user                        │
    │                        │ ④ filter by tag/level   │                        │
    │                        │──────── ⑤ encrypt ────▶│── ⑥ APNs/FCM ─────────▶│
    │                        │                        │     ⑦ SW showNotification
    │                        │                        │     ⑧ system banner       │

API 概要

Base URL
https://あなたのドメイン
セルフホスト時はあなたのドメインまたは Tunnel ドメイン
API バージョン
/v1
すべての動的 API にバージョンプレフィックス付き。静的アセットは /static/*
エンドポイントマップ
POST /v1/notify Agent による通知上報（中核）
GET /v1/notifications 通知履歴一覧
GET /v1/devices デバイス一覧
POST /v1/devices デバイス購読（登録）

GET /v1/keys API Key 一覧
POST /v1/keys API Key 新規作成
POST /v1/auth/register · login Passkey 登録 / ログイン
GET /v1/vapid-public-key VAPID 公開鍵（購読用）

認証方法

2 種類の認証情報があり、呼び出し元に応じて使い分けます。<b class="text-zinc-200">最小権限</b>：上報と受信は分離されており、Key が漏洩しても片方だけの影響で済みます。

KEY API Key（Bearer）
  • · Agent 上報 / 受信側ロングポール接続に使用
  • · Header：<code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">Authorization: Bearer ant_…</code>
  • · scope：<code class="mono text-[12px] text-blue-300">notify:send</code> 上報 · <code class="mono text-[12px] text-emerald-300">notify:receive</code> 受信 · <code class="mono text-[12px] text-amber-300">devices:read</code> 読み取り専用
  • · サーバーは argon2id ハッシュのみ保存、平文は作成時のみ表示
PASSKEY セッション Cookie
  • · ワークスペースのブラウザアクセスに使用（概要 / デバイス / Keys 管理）
  • · WebAuthn パスワードレスログイン、生体認証またはデバイスキー
  • · httpOnly Cookie、マルチデバイスセッションは独立して個別に取り消し可能
  • · クロスデバイス：プラットフォーム同期 / 一時接続ガイド / リカバリーコード
POST /v1/notify 中核

Agent がタスク終了後にこのエンドポイントを呼び出して通知を上報します。サーバーは API Key を検証し、所有者を特定し、通知を<b class="text-zinc-200">エンドツーエンド暗号化</b>で「有効かつレベル / タグが一致する」すべてのデバイスにプッシュします。

リクエストボディ パラメータ
title必須
string ≤ 120
 通知タイトル。例：<code>"デプロイ完了"</code>。システム通知のメインタイトルになります。
status必須
enum
 タスク結果：<code>success</code> 成功 · <code>error</code> 失敗 · <code>interrupted</code> 中断 · <code>info</code> 情報 · <code>warning</code> 警告。アイコン色とデバイスフィルタを決定します。
body任意
string ≤ 500
 通知本文。補足説明です。
deviceTags任意
string[]
 ルーティングタグ。空 = すべての有効デバイスにブロードキャスト。非空 = 「共通タグがある」または「タグなし（catch-all）」のデバイスのみに配信。≤10 個、各 ≤32 文字。
link任意
string (uri)
 通知タップ時に開くディープリンク。例：<code>pi://session/sess_8f3a2c</code>。
agentId / sessionId / cwd / model / durationMs任意 コンテキストメタデータ。追跡と統計に使用され、通知履歴に保存されます。
ttl / priority任意 <code>ttl</code> 有効期限（秒）（デフォルト 86400）；<code>priority</code> 優先度（デフォルト normal）。
cURL · 完全なリクエスト
curl -X POST https://あなたのドメイン/v1/notify \ -H "Authorization: Bearer ant_live_9f3a2c8e…" \ -H "Content-Type: application/json" \ -d '{ "title": "デプロイ完了", "status": "success", "body": "ビルド成功、本番環境にデプロイ済み", "link": "pi://session/sess_8f3a2c", "agentId": "deploy-bot", "sessionId": "sess_8f3a2c", "cwd": "/repo/prod-backend", "durationMs": 24000, "model": "anthropic/claude-4", "deviceTags": ["仕事"] }'
200 受領・配信完了
{ "id": "ntf_01J8XA…", "matched": 2, "results": [ { "device": "メインスマホ", "status": "sent" }, { "device": "オフィス Mac", "status": "sent" } ] }
400 一致するデバイスなし / パラメータエラー
{ "error": "購読済みデバイスがありません。先にワークスペースで購読してください" } // 401 · Key がないまたは無効（scope 不足時は 403） { "error": "invalid api key" }
配信ルール（タグルーティング + レベルフィルタ） 
deliver ⟺ device.enabled AND statusMatch AND tagMatch

statusMatch: device filter all=catch-all · error=errors-only · success=success-only
tagMatch:
  · no deviceTags on notification → broadcast to all enabled devices
  · no tags on device            → receives everything (catch-all)
  · both have tags               → delivers if ≥1 tag in common (ANY)

Web Push 購読（ブラウザ受信）

ブラウザは Service Worker + PushManager で購読し、バックエンドは VAPID 署名でプッシュします。<b class="text-zinc-200">ページを閉じていても受信できます</b>。iOS は「ホーム画面に追加」してスタンドアローンモードで実行する必要があります（iOS 16.4+）。

  1. <b class="text-zinc-200">① VAPID 公開鍵を取得</b> · <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">GET /v1/vapid-public-key</code>
  2. <b class="text-zinc-200">② Service Worker を登録</b> · <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">navigator.serviceWorker.register('/sw.js')</code>
  3. <b class="text-zinc-200">③ 権限を要求して購読</b> · <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">pushManager.subscribe(&#123; applicationServerKey &#125;)</code>
  4. <b class="text-zinc-200">④ 購読を上報</b> · endpoint + keys を <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">POST /v1/devices</code> で送信
フロントエンド購読 · コアコード
// 1. SW 登録 + VAPID 公開鍵を取得 const reg = await navigator.serviceWorker.register("/sw.js"); const { publicKey } = await fetch("/v1/vapid-public-key").then(r => r.json()); // 2. 購読（通知権限の許可が必要） const sub = await reg.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: urlBase64ToUint8Array(publicKey), }); // 3. バックエンドに報告（セッション Cookie 認証） await fetch("/v1/devices", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ endpoint: sub.endpoint, keys: sub.toJSON().keys, // { p256dh, auth } platform: "ios", // ios|mac|win|android|other userAgent: navigator.userAgent, }), });
⚠️ iOS の前提条件 「ホーム画面に追加」してスタンドアローンモードで実行する必要があります。そうしないと Safari は Notification / Push API を提供しません。
✅ Android はもっと簡単 Chrome/Edge は通常のタブから購読でき、FCM 経由です。ホーム画面に追加する必要はありません。
🔒 エンドツーエンド暗号化 ペイロードは購読の p256dh/auth 鍵で暗号化され、プッシュサービスは内容を読めません。
WS /v1/stream notify:receive 2 つ目の受信チャネル

ブラウザプッシュに加え、任意のデバイス / プラグインが <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">notify:receive</code> 権限の Key で WebSocket ロングポールを確立し、リアルタイム受信できます。デスクトップウィジェット、CLI デーモン、スマートホームブリッジに最適。ブラウザプッシュと並行稼働します。

接続の確立
GET wss://あなたのドメイン/v1/stream Authorization: Bearer ant_recv_9f3a… # notify:receive 権限が必要 Last-Event-Id: evt_01J8X3A1 # 任意、再接続時のレジュム用
サーバー → クライアント
// 接続成功後の最初のフレーム { "type": "hello", "conn_id": "c_9f2", "heartbeat_sec": 30, "resume_token": "evt_01J8X2" } // 新しい通知を受信 { "type": "notification", "event_id": "evt_01J8X3A1", "title": "デプロイ完了", "status": "success", "body": "本番にデプロイ済み", "deviceTags": ["仕事"] } // リプレイ終了 / ハートビート / エラー { "type": "replay_end" } { "type": "pong" } { "type": "error", "code": "resume_expired" }
クライアント → サーバー
// タグの購読 / 購読解除（空 = 全て） { "type": "subscribe", "tags": ["ops", "builds"] } { "type": "unsubscribe", "tags": ["ops"] } // 処理済みを確認（at-least-once） { "type": "ack", "event_ids": ["evt_01J8X3A1"] } // ハートビート（heartbeat_sec ごと、2 回連続未受信で切断） { "type": "ping" } // 再接続後、resume フレームでレジュム（Last-Event-Id ヘッダの代替） { "type": "resume", "resume_token": "evt_01J8X2" }
再接続とレジュム

再接続時に <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">Last-Event-Id</code> ヘッダ（または最初のフレームで <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">resume</code>）を送信すると、サーバーは直近 24h の未確認通知（リプレイウィンドウ）を再送し、その後リアルタイムストリームに移行します。保持期間を超えると <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">resume_expired</code> エラーを返します。クライアントは全履歴を再取得してください。
