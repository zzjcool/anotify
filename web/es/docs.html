Conectar Agent

El escenario principal de Anotify: <b class="text-zinc-200">cuando un Agent termina una tarea, la notificación se envía automáticamente a todos sus dispositivos</b>. La integración son dos pasos: cree una Key de reporte y luego envíe un POST cuando termine la tarea.

1 Crear una Key de reporte

Vaya a la página <a href="keys.html" class="text-indigo-300 underline decoration-indigo-400/30 underline-offset-2 hover:text-indigo-200">API Keys</a> y cree una Key con permiso <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">notify:send</code> (prefijo <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">ant_live_</code>). Guárdela inmediatamente.

2 Reportar al terminar la tarea

En un evento de finalización del Agent (p. ej. <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">agent_settled</code> de pi) o al final del script, incluya la Key y haga <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">POST /v1/notify</code>.

Configuración mínima · un curl para enviar a todos los dispositivos
curl -X POST https://su-dominio/v1/notify \ -H "Authorization: Bearer ant_live_9f3a2c8e…" \ -H "Content-Type: application/json" \ -d '{"title":"Despliegue completado","status":"success","body":"Build exitoso, desplegado a producción"}'

Autenticación

Dos tipos de credenciales, para dos tipos de llamadores. <b class="text-zinc-200">Mínimo privilegio</b>: envío y recepción están separados, por lo que una Key filtrada solo afecta a un lado.

KEY API Key (Bearer)
  • · Para reportes del Agent / conexiones long-poll del receptor
  • · Header: <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">Authorization: Bearer ant_…</code>
  • · scope: <code class="mono text-[12px] text-blue-300">notify:send</code> reportar · <code class="mono text-[12px] text-emerald-300">notify:receive</code> recibir · <code class="mono text-[12px] text-amber-300">devices:read</code> solo lectura
  • · El servidor solo guarda un hash argon2id; el texto plano se muestra una vez al crear
PASSKEY Cookie de sesión
  • · Para acceso al workspace desde el navegador (Resumen / Dispositivos / Keys)
  • · Login sin contraseña con WebAuthn, biometría o clave de dispositivo
  • · Cookie httpOnly; las sesiones multi-dispositivo son independientes y revocables individualmente
  • · Multi-dispositivo: sincronización de plataforma / guía de conexión / código de recuperación
POST /v1/notify Núcleo

Un Agent llama a este endpoint para reportar una notificación al terminar una tarea. El servidor valida la API Key, localiza al usuario y envía la notificación <b class="text-zinc-200">cifrada de extremo a extremo</b> a todos los dispositivos "habilitados y que coincidan en nivel/tag".

Parámetros del cuerpo de la petición
titleObligatorio
string ≤ 120
 Título de la notificación, p. ej. <code>"Despliegue completado"</code>, se muestra como título principal de la notificación del sistema.
statusObligatorio
enum
 Resultado de la tarea: <code>success</code> · <code>error</code> · <code>interrupted</code> · <code>info</code> · <code>warning</code>. Determina el color del icono y el filtrado de dispositivos.
bodyOpcional
string ≤ 500
 Cuerpo de la notificación, detalle complementario.
deviceTagsOpcional
string[]
 Tags de enrutamiento. Vacío = difundir a todos los dispositivos habilitados; no vacío = solo se entrega a dispositivos con tag en común o sin tags (catch-all). ≤10 tags, cada uno ≤32 caracteres.
linkOpcional
string (uri)
 Deep link que se abre al tocar la notificación, p. ej. <code>pi://session/sess_8f3a2c</code>.
agentId / sessionId / cwd / model / durationMsOpcional Metadatos de contexto para trazabilidad y estadísticas, almacenados en el historial.
ttl / priorityOpcional <code>ttl</code> validez en segundos (por defecto 86400); <code>priority</code> prioridad (por defecto normal).
cURL · petición completa
curl -X POST https://su-dominio/v1/notify \ -H "Authorization: Bearer ant_live_9f3a2c8e…" \ -H "Content-Type: application/json" \ -d '{ "title": "Despliegue completado", "status": "success", "body": "Build exitoso, desplegado a producción", "link": "pi://session/sess_8f3a2c", "agentId": "deploy-bot", "sessionId": "sess_8f3a2c", "cwd": "/repo/prod-backend", "durationMs": 24000, "model": "anthropic/claude-4", "deviceTags": ["trabajo"] }'
200 Aceptado y enviado
{ "id": "ntf_01J8XA…", "matched": 2, "results": [ { "device": "Teléfono principal", "status": "sent" }, { "device": "Mac de oficina", "status": "sent" } ] }
400 Sin dispositivo coincidente / error de parámetros
{ "error": "No hay dispositivos suscritos; suscríbase primero en el workspace" } // 401 · Key ausente o inválida (403 si scope insuficiente) { "error": "invalid api key" }
Reglas de entrega (enrutamiento por tags + filtrado por nivel) 
deliver ⟺ device.enabled AND statusMatch AND tagMatch

statusMatch: device filter all=catch-all · error=errors-only · success=success-only
tagMatch:
  · no deviceTags on notification → broadcast to all enabled devices
  · no tags on device            → receives everything (catch-all)
  · both have tags               → delivers if ≥1 tag in common (ANY)

Suscripción Web Push (recepción en navegador)

El navegador se suscribe vía Service Worker + PushManager; el backend envía con firma VAPID. <b class="text-zinc-200">Se recibe incluso con la página cerrada.</b> iOS requiere "Añadir a pantalla de inicio" y modo standalone (iOS 16.4+).

  1. <b class="text-zinc-200">① Obtener clave pública VAPID</b> · <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">GET /v1/vapid-public-key</code>
  2. <b class="text-zinc-200">② Registrar Service Worker</b> · <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">navigator.serviceWorker.register('/sw.js')</code>
  3. <b class="text-zinc-200">③ Solicitar permiso y suscribir</b> · <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">pushManager.subscribe(&#123; applicationServerKey &#125;)</code>
  4. <b class="text-zinc-200">④ Reportar suscripción</b> · enviar endpoint + keys vía <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">POST /v1/devices</code>
Suscripción frontend · código central
// 1. Registrar SW + obtener clave pública VAPID const reg = await navigator.serviceWorker.register("/sw.js"); const { publicKey } = await fetch("/v1/vapid-public-key").then(r => r.json()); // 2. Suscribir (requiere permiso de notificaciones) const sub = await reg.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: urlBase64ToUint8Array(publicKey), }); // 3. Reportar al backend (auth por Cookie de sesión) await fetch("/v1/devices", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ endpoint: sub.endpoint, keys: sub.toJSON().keys, // { p256dh, auth } platform: "ios", // ios|mac|win|android|other userAgent: navigator.userAgent, }), });
⚠️ Requisito de iOS Debe "Añadir a pantalla de inicio" y ejecutar en modo standalone, de lo contrario Safari no proporciona Notification / Push API.
✅ Android es más fácil Chrome/Edge puede suscribirse desde una pestaña normal vía FCM; no necesita añadir a pantalla de inicio.
🔒 Cifrado de extremo a extremo El payload se cifra con las claves p256dh/auth de la suscripción; el servicio de push no puede leer el contenido.
WS /v1/stream notify:receive Segundo canal de recepción

Además del push del navegador, cualquier dispositivo / plugin puede usar una Key con permiso <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">notify:receive</code> para establecer una conexión WebSocket long-poll y recibir en tiempo real. Ideal para widgets de escritorio, daemons CLI, puentes de domótica. Funciona junto al push del navegador.

Establecer conexión
GET wss://su-dominio/v1/stream Authorization: Bearer ant_recv_9f3a… # requiere permiso notify:receive Last-Event-Id: evt_01J8X3A1 # opcional, para reanudar tras reconectar
Servidor → Cliente
// primer frame tras conectar { "type": "hello", "conn_id": "c_9f2", "heartbeat_sec": 30, "resume_token": "evt_01J8X2" } // nueva notificación recibida { "type": "notification", "event_id": "evt_01J8X3A1", "title": "Despliegue completado", "status": "success", "body": "Desplegado a prod", "deviceTags": ["trabajo"] } // fin de replay / heartbeat / error { "type": "replay_end" } { "type": "pong" } { "type": "error", "code": "resume_expired" }
Cliente → Servidor
// suscribir / cancelar tags (vacío = todos) { "type": "subscribe", "tags": ["ops", "builds"] } { "type": "unsubscribe", "tags": ["ops"] } // confirmar procesado (at-least-once) { "type": "ack", "event_ids": ["evt_01J8X3A1"] } // heartbeat (cada heartbeat_sec; 2 perdidos = desconectar) { "type": "ping" } // tras reconectar, usar frame resume (reemplaza header Last-Event-Id) { "type": "resume", "resume_token": "evt_01J8X2" }
Reconectar y reanudar

Al reconectar, envíe el header <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">Last-Event-Id</code> (o un primer frame <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">resume</code>). El servidor reenvía las notificaciones no confirmadas de las últimas 24h (ventana de replay), luego entra al stream en vivo. Si supera la ventana de retención, devuelve error <code class="mono rounded bg-white/5 px-1.5 py-0.5 text-[12px] text-zinc-300">resume_expired</code>; el cliente debe obtener el historial completo.
