Flowline 流线 sequence as a journey

把一次运行当成一条邮路：触发、每一步、每个数据包都有位置。大卡片保证可读， 数据包沿贝塞尔边飞行，回放时按执行顺序点亮 —— 短链不再缩成图中央的一个小点。

短链首选 因果叙事 可横向扩展
强项

2–6 步的短链最好看：结构、顺序、数据同屏，非工程同事也能读懂。数据包让「东西真的流过去了」可感。

代价

7 列以上要横向滚动；长链的全局形状不如 Atlas。适合做默认视图的前半屏，不适合当唯一视图。

落地

复用 /v1/tasks + emissions；边是 SVG，节点是 DOM，沿用现有 dagre 的坐标即可。移动端自动降级为 Reel。

02 / 05

Atlas 图谱 the whole terrain

一张可缩放的地图：走过的路是实的，没走的分支是虚线幽灵，缩放、小地图、检查器都在。 保留现有「拓扑图」的心智，但把卡片、层级和未执行分支讲清楚。

默认推荐 全拓扑 可缩放
强项

复杂 trace 的全局形状：扇出、汇聚、重试、未执行分支一屏看完。检查器把时间与产出补在点击之后。

代价

节点多时要靠缩放；时间不是第一维，排障要再点一步。小图容易显得空，需要自动放大。

落地

现有 dagre + flograph 可直接演进；保留 .wf-node 契约，新增幽灵节点/检查器/小地图即可。

03 / 05

Split 分栏 inspect without losing the thread

左边是可扫的执行序列，右边是选中那一步的全部事实：耗时、节点、尝试、产出 JSON、错误， 以及全链耗时对照。自动巡览把「点一步看一步」变成可播放的讲解。

排障密度 产出/错误 自动巡览
强项

同一屏里结构 + 时间 + 原始数据，最接近真实排障：先扫序列，再点开失败那一步，产出就在旁边。

代价

拓扑感最弱；跨分支比较要来回点。右侧内容多，需要严格的信息层级，否则会变成表单。

落地

左轨用现有 buildSpans 顺序；右侧瀑布条复用 .wf-bar 的时间计算。无新依赖，交互全是 CSS + 局部重渲染。

04 / 05

Reel 胶片 a run you can read

像读一张运行收据：触发在页眉，每一步是一格胶片，产出原文就在下面。没有图、没有缩放， 手机上也能一口气读完。短链时它最有气质，长链时它最省心。

移动端首选 阅读优先 零布局计算
强项

手机上最好读；短链像一张运行收据，失败卡自然突出。实现最轻，性能最好，无图布局失败风险。

代价

长链会变成长滚动，并行分支的「同时发生」读不出来；桌面宽屏上信息密度偏低。

落地

纯 DOM/CSS，无坐标计算；可直接替换现有树视图，作为窄屏默认。产出用现有 emissions 渲染。

05 / 05

Ledger 账本 density without noise

把 trace 写成 `git log --graph`：一屏十步，树形导轨、状态字形、耗时、产出数都在一行里。 点开任意一行，原始 JSON 原地展开。给工程用户和窄屏的第二视角。

密度最高 工程感 可嵌日志
强项

10 步一屏，密度与速度都最高；状态、耗时、产出数一眼扫完，点开就是原始 JSON。适合嵌进事件流侧栏。

代价

图形表达最弱，非工程用户不友好；树形前缀在深链上会吃宽度，窄屏需横向滚或隐藏节点列。

落地

纯 DOM，固定行高；展开详情复用现有 emissions/日志组件。可作为 trace 页的「紧凑」切换，不替代主视图。

我的建议

上线默认用 Atlas 承载结构，再把 Flowline 的数据包与回放 借过来做「刚跑完」的前 3 秒；排障页用 Split，窄屏用 Reel， 事件流侧栏用 Ledger。五个方案共用同一份 tasks/emissions 数据与同一套 token， 不需要新库，也不会改后端契约。
