通知接收

这里决定「通知发到哪」——两条接收通道：浏览器推送订阅 + WebSocket 长连接（供插件/任意设备）。配合标签路由精确分发。

浏览器推送订阅

通过系统 Push 服务（APNs / FCM）送达，浏览器关闭也能收到

长连接接收 · 为插件与任意设备而生

任何设备 / 插件用 notify:receive 权限的 API Key 建立 WebSocket 长连接，服务端实时推送通知。 适合做桌面插件、CLI 守护进程、智能家居桥接等。与浏览器推送并行存在。

连接方式

$ wscat -c wss://api.anotify.dev/v1/stream \

-H "Authorization: Bearer ant_recv_…"

标签路由规则

上报通知时带 deviceTags 即可定向投递：不带标签 → 广播到所有启用设备； 带标签 → 只发到订阅了该标签的设备（无标签的设备是全收）。 与每台设备的「通知级别」过滤相互独立，需同时满足。

例如 Agent 上报： deviceTags: ["手机"] → 只有标了「手机」的设备收到
