API 接口文档

Anotify 提供一组 REST API，让 Agent、脚本与 CI 流水线在任务完成时上报通知，并由服务端把通知推送到你的所有设备。 所有接口基于 HTTPS + JSON，遵循 REST 语义与标准 HTTP 状态码。

Base URL
https://api.anotify.dev
私有化部署时为你的域名
API 版本
/v1
所有接口带版本前缀
接口地图
POST /v1/notify Agent 上报通知（核心）
GET /v1/notifications 通知历史列表
GET /v1/notifications/:id 单条通知详情
GET /v1/devices 设备列表
POST /v1/devices 订阅（注册）设备
PATCH /v1/devices/:id 更新设备（开关/级别/名称）
DEL /v1/devices/:id 移除设备
GET /v1/keys API Key 列表
POST /v1/keys 新建 API Key
POST /v1/auth/register/* Passkey 注册（begin/finish）
POST /v1/auth/login/* Passkey 登录（begin/finish）
POST /v1/devices/pair-link 生成跨设备配对链接
GET /v1/health 健康检查
GET /v1/vapid-public-key Web Push VAPID 公钥

认证方式

Anotify 有两类凭证，分别面向「人」和「机器」：

API Key 机器凭证 · Agent / 脚本上报

通过 Authorization: Bearer 请求头携带。仅用于 POST /v1/notify 等机器接口。服务端只存哈希，创建时明文仅展示一次。

Authorization: Bearer ant_live_9f3a2c8e…
Session 用户凭证 · 工作台 / 浏览器

Passkey（WebAuthn）登录成功后，服务端签发 HttpOnly Cookie 会话。 用于设备管理、Key 管理、通知历史等浏览器端接口。

POST /v1/notify 核心

Agent 在任务结束（agent_settled 事件触发）后调用本接口上报一条通知。服务端校验 API Key，定位所属用户， 把通知端到端加密推送到该用户所有「已启用且级别匹配」的设备。

请求头
Header 说明
Authorization必填 Bearer ant_live_… 你的上报 API Key
Content-Type必填 application/json
Idempotency-Key可选 幂等键。网络重试时传相同值可避免重复通知（服务端 24h 内去重）

请求体参数

按用途分组：内容决定通知展示什么，上下文用于回溯与统计，投递控制影响推送行为。

内容 · 通知展示
title必填
string ≤ 120
 通知标题，如 "部署完成"。会作为系统通知的主标题。
status必填
enum
 任务结果：success 成功 · error 失败 · interrupted 中断 · info 信息 · warning 警告。决定图标颜色与设备过滤。
body可选
string ≤ 500
 通知正文，补充说明，如 "构建成功，已发布到 prod"。
link可选
string (uri)
 点击通知后打开的深链，如 pi://session/sess_8f3a2c 或 https://…，直达 Agent 会话或构建详情。
上下文 · 回溯与统计
agentId可选
string
 上报的 Agent 标识，如 "deploy-bot"。用于按 Agent 统计与筛选。
sessionId可选
string
 Agent 会话 ID，如 "sess_8f3a2c"。配合 link 实现回到会话。
cwd可选
string
 工作目录 / 项目路径，如 "/repo/prod-backend"。识别通知属于哪个项目。
durationMs可选
integer
 任务耗时（毫秒），如 24000。用于展示「耗时 24s」。
model可选
string
 使用的模型，如 "anthropic/claude-4"。便于追踪不同 Agent 后端。
tags可选
string[]
 自定义标签，如 ["deploy","prod"]，用于工作台分组与检索。
metadata可选
object
 任意键值对（≤ 4KB），随通知存储，供扩展与详情页展示。
路由 · 标签定向
deviceTags可选
string[]
 定向投递到「订阅了这些标签」的设备。省略或 [] = 广播到所有启用设备；带标签 = 只发到匹配设备 （无标签的设备是全收）。与设备状态过滤独立，需同时满足。 例如 ["手机"] → 只有标了「手机」的设备收到。 注意与下面的 tags（通知标签，仅用于检索）区分。
投递控制 · 推送行为
priority可选
enum
 优先级：low · normal(默认) · high · critical。映射 Web Push Urgency 头，影响系统是否立即唤醒设备。
ttl可选
integer(秒)
 通知有效期，默认 86400。设备离线时，推送服务在 TTL 内保留，过期丢弃。
collapseKey可选
string
 折叠键。相同键的通知互相覆盖（只显示最新），适合「构建进度」这类持续更新。
silent可选
boolean
 默认 false。为 true 时只写入历史、不实际推送（用于记录但不打扰）。

调用示例

cURL · 完整请求
curl -X POST https://api.anotify.dev/v1/notify \ -H "Authorization: Bearer ant_live_9f3a2c8e…" \ -H "Content-Type: application/json" \ -H "Idempotency-Key: build-20260802-001" \ -d '{ "title": "部署完成", "status": "success", "body": "构建成功，已发布到生产环境", "link": "pi://session/sess_8f3a2c", "agentId": "deploy-bot", "sessionId": "sess_8f3a2c", "cwd": "/repo/prod-backend", "durationMs": 24000, "model": "anthropic/claude-4", "priority": "normal", "tags": ["deploy", "prod"] }'
200 OK 已接收并分发
{ "id": "ntf_01J8XA…", "status": "delivered", "delivered": 3, "failed": 1, "results": [ { "deviceId": "dev_9f3a", "platform": "ios", "status": "sent" }, { "deviceId": "dev_2b1d", "platform": "mac", "status": "sent" }, { "deviceId": "dev_77aa", "platform": "win", "status": "failed", "reason": "410 Gone" } ] }
4xx 常见错误
// 401 · Key 缺失或无效 { "error": "unauthorized", "message": "invalid or missing API key" } // 400 · 参数校验失败 { "error": "invalid_params", "message": "title is required" } // 404 · 没有可用设备 { "error": "no_devices", "message": "no enabled devices, subscribe first" }
Shell · 任务结束自动上报
# 在脚本/CI 末尾调用 anotify_send() { curl -s -X POST "$ANOTIFY_URL/v1/notify" \ -H "Authorization: Bearer $ANOTIFY_KEY" \ -H "Content-Type: application/json" \ -d "{\"title\":\"$1\",\"status\":\"$2\"}" } make deploy && anotify_send "部署完成" success \ || anotify_send "部署失败" error
JavaScript / Node
await fetch("https://api.anotify.dev/v1/notify", { method: "POST", headers: { Authorization: `Bearer ${process.env.ANOTIFY_KEY}`, "Content-Type": "application/json", }, body: JSON.stringify({ title: "构建完成", status: "success", durationMs: Date.now() - t0, }), });

错误与状态码

所有错误返回统一结构 { "error": "...", "message": "..." }， 并配合标准 HTTP 状态码：

状态码 error 含义
200 — 成功
400 invalid_params 参数缺失或校验失败
401 unauthorized API Key 缺失 / 无效，或未登录
403 key_disabled API Key 已被停用
404 not_found / no_devices 资源不存在 / 无可用接收设备
409 duplicate 幂等键重复，请求已被处理
429 rate_limited 超出限流，稍后重试
500 internal 服务端错误

限流与幂等

限流

每个 API Key 默认 60 次/分钟。 响应头携带 X-RateLimit-Remaining 与 X-RateLimit-Reset， 超限返回 429。

幂等

上报时传 Idempotency-Key， 服务端 24h 内对相同键去重，网络重试不会产生重复通知，返回首个结果。

GET /v1/notifications Session

查询当前用户的通知历史（工作台「最近通知」数据源），支持筛选与分页。

Query 参数
status可选 按状态筛选：success|error|interrupted|info|warning
agentId可选 按 Agent 筛选
tag可选 按标签筛选
limit可选 每页条数，默认 20，最大 100
cursor可选 分页游标（上一页响应中的 nextCursor）
响应 · 200 OK
{ "data": [ { "id": "ntf_01J8XA…", "title": "部署完成", "status": "success", "agentId": "deploy-bot", "durationMs": 24000, "delivered": 3, "createdAt": "2026-08-02T08:14:34Z" } ], "nextCursor": "ntf_01J8WZ…" }
GET /v1/notifications/:id Session

获取单条通知的完整详情，包含正文、metadata 与每台设备的投递结果。

GET /v1/devices Session

列出当前用户的所有接收设备。

POST /v1/devices Session

注册一台设备的 Web Push 订阅（前端拿到 PushSubscription 后上报）。

请求体
{ "endpoint": "https://web.push.apple.com/Q…", // Push 服务地址 "keys": { "p256dh": "BNRG…", // 端到端加密公钥 "auth": "iHeX…" // 加密认证密钥 }, "platform": "ios", // ios|mac|win|android|web "name": "主力手机" // 可选，自定义名称 }
PATCH /v1/devices/:id Session

更新设备的接收开关、通知级别或名称（对应设备管理页的操作）。

enabled可选 接收开关。false 时该设备不再收到推送
filter可选 通知级别：all 全部 · error 仅失败 · success 仅成功
name可选 设备自定义名称
DEL /v1/devices/:id Session

移除设备订阅，彻底停止接收（返回 204 No Content）。

WS /v1/stream notify:receive 接收通道

除浏览器推送外，Anotify 提供第二条接收通道——WebSocket 长连接。 任意设备 / 插件用 notify:receive 权限的 API Key 建立持久连接，服务端实时推送通知帧。 适合做桌面插件、CLI 守护进程、智能家居桥接等，与浏览器推送并行。

建立连接
WebSocket 握手
GET wss://api.anotify.dev/v1/stream Authorization: Bearer ant_recv_9f3a… # 需 notify:receive 权限 Last-Event-Id: evt_01J8X3A1 # 可选，断线续传
服务端 → 客户端
// 连接成功后第一条 { "type": "hello", "conn_id": "c_9f2", "heartbeat_sec": 30, "resume_token": "evt_01J8X2" } // 收到新通知 { "type": "notification", "event_id": "evt_01J8X3A1", "title": "部署完成", "status": "success", "body": "已发布到 prod", "deviceTags": ["工作"], "link": "pi://session/sess_8f3a", "sent_at": "2026-08-02T09:41:02Z" }
客户端 → 服务端
// 只订阅某些标签（默认全收） { "type": "subscribe", "tags": ["工作", "告警"] } // 确认已收到（用于重放去重） { "type": "ack", "event_ids": ["evt_01J8X3A1"] } // 心跳（每 heartbeat_sec 一次） { "type": "ping" }
断线续传

重连时带 Last-Event-Id，服务端从 24h 缓冲重放未确认事件。

标签订阅

用 subscribe 帧动态收窄到指定标签，默认接收全部。

权限隔离

需 notify:receive 权限的 Key，与上报 Key 分开，互不波及。

GET /v1/keys Session

列出 API Keys。出于安全，只返回前缀，永不返回完整 Key。

POST /v1/keys Session

新建 API Key。完整明文仅在本次响应中返回一次，服务端随后只存 SHA-256 哈希。

响应 · 201 Created（仅此一次含完整 Key）
{ "id": "key_2b1d8e", "name": "本地开发", "key": "ant_live_9f3a2c8e4d5b6a7f", // ⚠️ 只出现这一次 "prefix": "ant_live_9f3a", "createdAt": "2026-08-02T08:14:34Z" }

认证 · Passkey（WebAuthn）

遵循 WebAuthn 标准两段式流程：begin 下发挑战， 浏览器调起系统生物识别，finish 校验并完成。

POST /v1/auth/register/begin 下发注册挑战（PublicKeyCredentialCreationOptions）
POST /v1/auth/register/finish 校验 attestation，创建用户 + 恢复码
POST /v1/auth/login/begin 下发登录挑战（支持 conditional UI）
POST /v1/auth/login/finish 校验 assertion，签发 HttpOnly 会话
POST /v1/devices/pair-link Session

生成一次性跨设备配对链接（5 分钟有效、仅用一次）。新设备打开链接临时获得登录态， 随即为本机创建绑定当前账号的新 Passkey——解决「电脑注册、手机登录」的跨生态问题。

GET /v1/health

健康检查，用于探活与监控。

{ "ok": true, "vapid": true, "version": "0.2.0" }
GET /v1/vapid-public-key

返回 Web Push 的 VAPID 公钥，前端订阅 Push 时用它标识应用服务器。
