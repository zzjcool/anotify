核心概念

整份文档只用五个名词：Event、Rule、Task、Node、Trace。这页把每个名词钉死——它是什么、长什么样、举一个具体例子——然后画一张图说明它们怎么串起来。后面所有页面都按这套叫法写。

五个名词

五个词各自回答一个问题：发生了什么（Event）、要不要动手（Rule）、动手这件事本身（Task）、谁来动手（Node）、整件事怎么被查（Trace）。括号里是代码原名。

Event event
触发源在某一刻发生的事，原样入库；事件只陈述事实，不含任何判断。
例：GitHub 送来一条 pull_request.opened，入库成一行 source=github、type=pr.opened、payload 里带 PR 号与 diff 链接。
Rule rule
一条 match 条件配一个 action，决定某类事件要不要引起某个动作；规则不改事件，只决定做不做、做什么。
例：match: source=github AND type=pr.opened → action: 在节点上跑 review-pr。同一事件还能同时命中另一条规则「推手机通知」。
Task task
规则命中后落地的一行待办，带租约和状态机；它是「谁去做、做到哪一步」的唯一载体。
例：task_id=8f21，命令 review-pr，参数 {pr: 431}，状态依次 pending → assigned → acked → running。
Node node
一台注册过的机器，本机 config.yaml 里声明自己能跑哪些命令名；中枢只按名字派活，不知道命令内容。
例：node: mbp-16，注册了 review-pr 与 run-tests 两个命令，max_concurrency=2。
Trace trace_id
从最初那个事件到最后一个任务的因果链，事件、规则判定、任务状态全部挂在同一个 trace_id 下。
例：trace=tr_7c1a，下挂 1 个事件、2 条规则命中、1 条剪枝记录、2 个任务。

它们怎么串起来

一条主链，两头是两个 sink。触发源产生事件，规则把事件翻译成任务，任务落到节点上执行，结果回来可以变成新事件，也可以变成一条推手机的通知。

读法：箭头左边是数据，右边是执行。Event 和 Task 是链上真正被存下来的两样东西（入库存一行），Rule 和 Node 是两端的能力：一个负责判定，一个负责动手。

一个事件能引出几件事

规则不是互斥的选择题。同一个事件命中几条规则，就产出几个任务，全部下发。没命中的规则不会被丢掉，而是在 trace 上留一条剪枝记录和原因。

扇出，不收集。一个事件引出多个任务是天然支持的（一次写入多行）。反过来「等这组任务都回来再继续」本期不做——那件事放在节点内部自己并行、自己汇总。任务的结果本身也可以是一条新事件，再命中规则就是接力。

两类 sink，永不混用

链尾有两条出口，语义完全不同：一条给人，一条给机器。它们不共用代码路径，也不共用同一套「失败怎么办」的假设——把两条混在一起，最终会得到既保证不了送达、又保证不了结果的中间态。

human sink · 推手机

给人看的。任务跑完了、或某个事件值得一看，就推一条到你手机。

  • 投递：尽力而为。设备离线、推送服务抽风，这条就没了。
  • 失败：不重试、不补发，不为此建持久队列。
  • 回报：不回报结果。你点没点开，对系统没有意义。
machine sink · node agent

给机器干的。任务必须真的在某个节点上被执行，并落到一个明确结局。

  • 投递：至少一次。租约 30s、心跳 10s、退避重试 10s → 60s → 300s、重试用尽进死信。
  • 失败：租约到期即重派，max_attempts 用尽落 failed。
  • 回报：必须回报。acked 只是接单确认，不是完成；不回报就不算做过。
判断标准：这条投递丢了会不会有人受损。丢一条手机通知最多是晚知道十分钟；丢一个任务等于没人干活，所以两条出口的保证级别不可能一致。

一次旅程（文字版）

把上面的名词按时间排一遍，就是一次完整的调用。完整的时序图在下一页，这里先记住四步。

事件入库
触发源发来一次调用（或者 cron 到点），中枢把它存成一行 event：source、type、payload、trace_id、span_id。入库即完成，之后所有判定都基于这条记录，不基于原始请求。
规则匹配
拿这条事件去比所有规则的 match。命中的规则各自产出一个 task，有多条就产出多个，全部下发。命中零条的，不产任务，但在 trace 上记一条 pruned 和原因。
任务派发
每个 task 按标签选出可用节点，带租约下发：中枢只发命令名和参数，节点用注册过的 argv 执行。节点 acked 表示接单，随后 running，心跳持续续租。
结果回流
节点回报结果，任务落 succeeded 或 failed。结果本身可以是一条新事件——再命中规则就是接力；不需要接力的，走 human sink 推手机。
