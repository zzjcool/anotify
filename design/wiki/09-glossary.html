术语表

前面八页用到的名词、字段名、状态名都在这里，一个词一行，只给一句话。写代码、读 trace、查配置时对照用；每条的定义展开在对应正文页，这里不重复论证。

本页只收当前模型的词汇。旧模型的求值类名词已整体作废，不在此列——若在别的文档里看到它们，按 _MODEL-V2.md 的废弃表处理。

接口

这一组是四层里最上面的一层。先把词序记住：接口 → 能力 → 执行器 → 图， 下面的词条都只在这个方向上解释：接口定义契约，能力是执行器对它的实现，边只连接口。

接口 interface
一份契约，由中枢侧定义并版本化：name@version + kind + params_schema + outputs。出口名只能来自这里——执行器没有命名权，只能说「我实现了哪个接口」。存在 interface_versions 表，append-only。
接口版本 name@version
接口的具名引用，如 review@1。两个版本就是两个接口：review@1 与 review@2 可并存，旧机器继续实现 @1，迁移期不强制升级。代价是图里同名接口会出现两个版本，所以控制台必须显式显示版本号。
参数结构 params_schema
接口定义里的 JSON Schema。派发前用它校验 params，不合格就不建任务。它是「参数不对」与「图不对」「行为不对」区分开的那一层——没有它，参数错误会被当成分支没走到。
内置接口 builtin
随项目发布的接口（interfaces/builtin/），由项目维护、进 git 走 review。本期共 10 个：github / cron / watch / http / review / implement / test / notify.phone / notify.webhook / log。表里的 source = builtin。
自定义接口 custom
用户自己在中枢配置目录里追加的接口。同一套格式、同一套版本化，加载后与内置没有区别，只靠 source = custom 区分来源。
未知接口 unknown_interface
执行器上报的 implements 指向一个中枢里不存在的接口。拒绝该能力，不自动创建同名接口——接口必须先在 git 里有定义。
节点类型不符 kind_mismatch
执行器声明的 kind 与接口声明的 kind 不一致，如拿 pipe 去实现 notify.phone（end）。注册时直接拒绝。
版本不受支持 unsupported_interface_version
接口名在、但那个版本不在。和 unknown_interface 分开报，是因为修法不同：一个是名字写错，一个是版本号写错。
参数不合格 param_schema
剪枝原因之一：params 没通过目标接口的 params_schema，不建任务，trace 上记 pruned / reason=param_schema。与 no_edge 区分：那是图里没这行边，这是边在、参数不对。

节点与执行器

节点 Node node
参与流转的一个实体，按端口形状三选一：origin / pipe / end。没有第四种。它不是机器——机器见下面的「执行器」。
种类 kind
节点在链上的位置，按端口分：origin（只出）、pipe（有进有出）、end（只进）。
源头、触发器 origin
只有出口的节点，负责产生事件：GitHub webhook、cron、watch、外部 API。它没有入边，所以永远不会被派任务。
管道 pipe
有进有出的节点：review / implement / test。任务落在它身上，跑完必须回报 out。
终点 end
只有入口的节点，跑完不产生下游：推手机、写日志。outputs 为空数组，out 恒为 null。
推手机
最常见的一个 end 接口（notify.phone）的实现。尽力而为、可丢、不回报 result，没有租约也没有重试。
能力清单 manifest
执行器上报的「我实现了哪些接口」：implements: [{interface, version}] 加各自的 sticky / idempotent 等声明。不写 outputs（出口由接口给定），不含 argv 原文。
执行器 id runner_id
一台执行器的稳定标识，和凭据一一对应。改名字不改 id。
实例 runner_instance
执行器进程（手）。一台执行器可以跑多个实例，各自申报 concurrency / inflight / status。
标签 label
中枢赋给执行器的分组名，用来圈定候选实例。接口实现决定「能不能做」，标签决定「让谁做」。
在跑数 inflight
实例当前正在跑几个任务。派发按它做「最少负载优先」。
并发 concurrency
实现级并发上限，执行器本地声明。实际并发取三层上限的 min。
max_instances
一台执行器允许跑几个实例，默认 20。防的是凭据扩散：每个实例一份 token，越多越难收。

能力与出口

能力 capability
不是「我能做什么」，而是某台执行器对某个接口的实现，就是一个二元组 (runner_id, interface_id)，存在 capabilities 表。 它不自带出口——出口是它实现的接口给的。路由的单位是接口，不是能力；能力决定「谁能跑」，接口决定「跑完往哪走」。
实现 implements
执行器在本地配置里声明「我实现了哪个接口」，如 implements: review@1。它不再写 outputs，出口集合由接口给定；也不允许只实现一部分——实现 review@1 就必须两个出口都能走。
出口 output / port
接口定义里的一个命名点（outputs 数组的一个元素）。跑完之后执行器选一个，走法就是回报它的名字。它是字符串，不是条件。
边 edge
(from_interface, from_port) → to_interface 三元组，路由表的一行。两端都是接口，不引用任何机器——换机器不影响图。
出口表 edges
全部边的集合，路由的唯一依据。主键 (from_interface, from_port, to_interface)，查询是一次索引命中。存的是 interface_versions.id（ifc_...）而不是 name@version，所以改名、加版本都不影响已有的边。
from_interface
边的起点，产出口的那个接口（ifc_...）。触发器的这一端也走接口，如 github@1。
from_port
边从哪个出口出发。必须是 from_interface.outputs 里的一个，静态检查会拒给不存在的出口名。触发器的这一列就是接口的出口名，如 pr_opened。
to_interface
边的终点，下一个接口（ifc_...）。同一个 (from_interface, from_port) 可以有 N 行，就是 N 个下游。
出口集 outputs
接口定义里那句「这个接口可能怎么结束」，它是契约，不是申报。执行器无权增减——review@1 就只能是 [fix, clean]。
源的出口声明 emits
触发器在 config.yaml 里声明「我产出哪些事件、各通向哪些接口」。中枢只收到这些事实，不收到任何 webhook 逻辑。
路由 routing
取 (source, type) 或 (接口, out) 当键，查 edges 拿 N 行，再用目标接口的 params_schema 校验参数、按接口找执行器。没有条件求值、没有优先级、没有表达式。
参数表 argv
每个接口实现对应的真实参数数组，写在执行器本地 ~/.anotifyd/config.yaml 的 implements[].argv，永不上传。中枢不知道它长什么样。
execve
唯一执行方式：拿 argv 数组直接 exec，不经 shell。禁止 /bin/sh -c，所以参数不会被二次解析。
未知接口 unknown_interface
中枢把某个接口派给这台执行器，但它没在 implements 里声明实现过。中枢不猜、不改写、不换一个实现了该接口的执行器重试。
幂等 idempotent
接口实现是否只读无副作用，默认 false。它决定执行器下线时任务怎么收场：true 直接放弃，false 放弃加告警加人工确认。
可续传 resumable
接口实现对应的命令是否支持断点续传。true 时执行器下线可重派到新机器，从中断点继续。
粘性 manifest.implements[].sticky
这个实现在派发时是否要求固定实例（共享工作目录、增量编译）。默认关闭——结果存在中枢，下游不需要回原机器。

任务

任务 Task task
「让某个接口实现跑一次」的记录加它的执行状态，同时就是 trace 上的一个 span。最小调度单位。
任务 id tsk_
任务 id 前缀，值同时充当该任务的 span_id。trace 上看到的每个任务 span 都有对应的 tsk_ 行。
派发 dispatch
查表得到 N 个接口，全部建任务（每个只建一个，不是每个实现建一个），然后按接口找实现了它的执行器。不择一、不排序、不丢弃。
回报 report
执行器跑完提交 status + out（外加 summary / artifacts）。中枢只认回报，不反推业务语义。
结果 result
终态时执行器回报的内容，上限 8KB。更大的输出留在执行器本地，回执只带截断后的结果和本地日志位置。
出口回报 out
我选了哪个出口，null 表示到此为止。一个字段表达两件事：有没有下游、有哪个下游。只在跑完之后才说得出来。
状态 status
九态状态机里的当前值，是唯一能回答「这个任务卡在哪」的字段。status 与 out 正交：失败也可能要走修复分支。
幂等键 idempotency_key
去重键：同一个 key 的重复投递应当只落一个任务。本期范围里没有定义这个字段，重复触发就是重复任务，防重复靠把图收紧加 daily_budget 兜底。
生命周期 lifecycle
接口实现可声明四项：expiresInSec 硬过期到点即放弃绝不重派 / retryable 是否允许中枢重派 / maxAttempts 重派上限 / resultTtlSec 到期只清 result 不清行。

运行时

九态状态机
pending → assigned → acked → running → succeeded / failed / canceled / abandoned，另有 lease_expired 中间态。中间态不是终态。
租约 lease_until
这个任务被某实例占用的截止时刻。心跳每 10s 把它推到 now + 30s；心跳停了就是失联。
租约到期 lease_expired
租约失效的中间态。attempts 没用尽就回 pending 重派，用尽则 abandoned。
接单 ack
接单确认，不是完成。执行器说「这单我接了」，租约才正式计时；结束只看 result 回报。
心跳 heartbeat
每 10s 一次续租，不是保活探针。TTL 30s 除心跳 10s = 允许连丢两次；判定由中枢做，不由执行器自报。
attempts
中枢派发次数，租约回收也算一次。上限 3，退避 10s → 60s → 300s。
internal_attempts
执行器在机器上自己重试的次数，不消耗中枢 attempts。由 manifest.implements[].retries 约束。
退避 backoff
重派的间隔序列 10s → 60s → 300s。重派期间不通知人，用尽才转 failed 进 DLQ。
放弃 abandoned
不重试、必通知。不等于成功，也不等于静默丢弃；和 failed 的区别正在「不重试」。
死信 DLQ
重试耗尽的投递落到这里等人工看，不静默消失。这是 pipe 必须回报的代价。
扇出 fanout
一次查表拿到 N 行就建 N 个任务，互不依赖、互不等待。实现就是同一事务里 INSERT 多行，本期无条件支持。收集（join）不做。
接力 chain
任务回报的 out 查到 edges 里的一行，就建下一跳任务。同一条 trace_id 延续，hop 加一，path 追加接口名。
落点表 runner_pins
粘性路由的查表结果。首次选完写进去，之后同一 key 一律查表，不重新算。默认派发不碰这张表。
sticky_key
由 trace、目标接口、选择器三段算出的哈希。只在实现声明了 sticky 时使用。

安全与限额

闸 G1
allow_chain：不显式开启就不接力。默认关，不可配。
闸 G2
max_hops：深度上限，默认 10，硬顶 32。它是外显上界，真正的终止性由 path 去重保证。
闸 G3
path 去重：目标接口已在本次行程里就静默剪枝。隐含生效，不可配。
闸 G4
max_tasks：单 trace 的任务数上限，默认 100，硬顶 1000。
闸 G5（已废弃）
付费任务数。已从设计里删掉，任何新配置都不该再引用这个编号。
闸 G6
max_duration：单 trace 总时长上限，默认 24h，硬顶 7d。到点不再派生，也是缺失 out 时的兜底。
硬顶
写在代码里的上限，配置只能往下改不能往上改。改硬顶等于改代码加发版，不走配置。
三层覆盖
同一类限额的三层配置：全局 env → 单图 → 代码硬顶。前面两层可改，最后一层只能改代码。
每日配额 daily_budget
这张图每天能建多少任务。用尽后新命中不建任务、记 pruned。成本可预测靠它加 max_tasks 两个数。
派生凭据 jti
派生 JWT 里的一次性 id。claim 还含 trace / span / hop / maxHop / branchBudget / exp，跳数由中枢签发，执行器改不动。
branch_nonces
已消费 jti 的表。消费 jti、建任务、扣额度在同一个事务里，重放直接失败。
branchBudget
本次派生还剩多少额度，由执行器自主分配。额度用尽必须可见，绝不静默失败。
budget_exhausted
额度用尽的三件套：返回 409、span 上写一条 event、控制台标注。少一件就等于静默失败。
凭据 token
执行器唯一凭据，一一对应一个 runner_id。泄漏即继承这台机器全部标签，这是已知代价；可撤销后重发。

版本

graph_versions
出口图的版本表，append-only：一整张图（全部 edges 行加各接口的 outputs）存一份快照。图是整体，拆开钉就回答不了「当时有没有这条边」。
node_manifest_versions
执行器上报的 implements 清单的版本表。执行器不报版本号，中枢按内容算哈希得到版本，所以「声称的实现」和「实际内容」不会分叉。
registry_versions
接口注册表（接口名到参数形状）的版本表。中枢只知道名字，形状的变更也要钉版本。接口自身的定义以 interface_versions 为准，这张表记的是注册侧的视图。
content_hash
版本内容规范化后的哈希，带唯一约束。内容没变就不产生新版本，版本膨胀被挡住。
版本 id 格式
<prefix>_<UTC>_<hash8>，例如 grf_20261024T090402Z_5e7c1b0f。人眼能看出时间和前缀，机器能校验前八位哈希。
钉 hash 不钉时间
trace 上记的是不可变的版本 id，不是「按时间反查当时生效的版本」。补录、回滚、跨时区导入都会打乱时间顺序，但动不了已经算好的 hash。
叠加图 overlay
把「图里有什么」和「这次走了什么」叠在一张图上的视图。亮实线 = 走过，灰虚线 = 有边没走，红虚框 = 剪枝。

事件与行程

事件 Event event
系统里唯一的事实单位：外部触发写一行，任务回报也写一行，两者形状相同，过的是同一张出口表。
事件来源 event.source
事件从哪来，如 github / cron / watch / agent。和 type 一起构成查表的起点 origin:<名字>。
类型 type
事件类型，写成 <域>.<动作>，如 pull_request.opened、task.succeeded。它同时也是触发器的 from_port。
载荷 payload
事件携带的 JSON 主体。中枢只存不解释——路由不看它，所以它不会影响走哪条边。
链路 id trace_id
一次触发引起的全部工作共用的 id。根事件生成，后继事件与任务一律沿用，不新开。
span id span_id
一次工作的唯一标识。本项目里它就是任务 id（task.id），不另发号。
父 span parent_span_id
哪个任务派生出来的（tasks.parent_task_id）。根事件直接派生的任务，这一列为空。
跳数 hop
接力深度。根事件 0，每派生一次加一。上界由 max_hops（G2）管。
深度 depth
这个任务在派生链里的层级，与本任务 path 的长度一致。和 hop 说的是同一件事，一个从行程看、一个从跳数看。
行程 path
从根到本任务这条具体路径的接口名序列，用于去重剪枝。不是整条 trace 的接口集合——同一个接口在另一条分支上照样能跑。
剪枝 pruned
本该建任务却没建时留下的记录，必须带原因。静默指不报错不暂停，不是不记录。
no_edge
剪枝原因之一：edges 表里查不到 (from_interface, from_port) 这一行。图是静态的，所以这个原因不跑也能知道。
抑制 suppressed
本该发出去却没发的记录，用于回答「通知去哪了」。它是显式的丢弃，和「跑过但失败」区分开。
链路 Trace trace
一条完整链路的视图，按 trace_id 把事件、查表结果、任务状态聚到一起，是事后回答「走了哪条路」的唯一入口。
span Span
链路上的一段执行，有起止时间。本项目里 span 就是 task——一个任务一个 span，不另建表。一次查表没有时长，只在事件 span 上留痕。
四个「没做成」别混。pruned 是任务压根没建（表里没有这条边 / 行程里已有该接口 / 参数不合 schema / 被限额挡下）；suppressed 是本来要发的没发； failed 是跑过但失败、可重试；abandoned 是不再重试且必须通知。混用任何一个，事后就再也解释不清「这次为什么没发生」。

前缀速查

id 前缀一眼就能看出对象类型。标「本期不用」的，是这个前缀没有对应的对象——不是还没写，而是设计上就不需要。

前缀 代表 说明
evt_ 事件 event 外部触发与任务回报都用它，事件只追加不修改。
trc_ 链路 trace 本期不用：没有独立的 trace 行，链路是按 trace_id 把事件和任务聚合出来的。
spn_ span 本期不用：span_id 就是 task.id，走的 tsk_ 前缀。
tsk_ 任务 task 任务 id，与 span_id 同值。trace 上的任务 span 就是它。
ifc_ 接口版本 interface_versions 接口的一个具体版本，格式 ifc_<UTC>_<hash8>，append-only。edges 与 capabilities 存的都是这个 id。
grf_ 图版本 graph_versions 出口图版本，格式 grf_<UTC>_<hash8>，append-only。一份快照含全部 edges 与 capabilities。
nmf_ 版本 node_manifest_versions 执行器 implements 清单版本，由内容哈希算出，不由执行器自报。
reg_ 版本 registry_versions 能力注册表版本，例 reg_20261023T101500Z_a1b2c3d4。
inst_ runner_instances 执行器实例，一台机器可以有多个。带 concurrency 与 inflight。
fan_ 扇出批次 本期不用：没有「批次」这个对象，扇出只是一次查表后 INSERT 多建几行任务，不需要批次 id。
