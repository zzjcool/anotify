事件与链路

事件 Event event
系统里唯一的事实单位：外部触发写一行，任务结果也写一行，两者形状相同，过的是同一套路由。
来源 source
事件从哪来，如 github / cron / watch / agent。edges 表查表键的第一维。
类型 type
事件类型，写成 <域>.<动作>，如 pr.opened、task.succeeded。
载荷 payload
事件携带的 JSON 主体。事件类型与来源构成查表的键，如 payload.repo。
链路 id trace_id
一次触发引起的全部工作共用的 id。根事件生成，后继事件与任务一律沿用，不新开。
span id span_id
一次工作的唯一标识。本项目里它就是任务 id（task.id），不另发号。
父 span parent_span_id
哪个任务派生出来的（tasks.parent_task_id）。根事件直接派生的任务，这一列为空。
跳数 hop
接力深度。根事件 0，每派生一次加一。上限由 max_hops（G2）管。
深度 depth
这个任务在派生链里的层级，与本任务 path 的长度一致。和 hop 说的是同一件事，一个从路径看、一个从跳数看。
路径 path
从根到本任务这条具体路径的 rule_id 序列，用于环检测。不是整条 trace 的能力集合——同一个能力在另一条分支上照样能跑。
链路 Trace trace
一条完整链路的视图，按 trace_id 把事件、查表结果、任务状态聚到一起，是事后回答「走了哪条路」的唯一入口。
span Span
链路里的一个节点，有起止时间。一个任务是一个 span，一次查表也可以画成一条零长度的 span。
剪枝 pruned
条件成立却被挡下时留下的记录，必须带原因：环 / 深度 / 预算 / 时长。静默指不报错不暂停，不是不记。
抑制 suppressed
本该发出去却没发的记录，用于回答「通知去哪了」。它是显式的丢弃，和「跑过但失败」区分开。
链路终态 trace.settled
整条链路的终结标记：所有 span 都进了终态才为真。控制台靠它区分「跑完了」和「还在跑、别急着下结论」。

节点与种类

节点 node
一切参与流转的实体。可能是机器、webhook、手机。分类只看端口形状。
种类 kind
source / worker / sink 三选一，没有第四种。
源 / 触发器 source
只有出口、没有入口的节点。把外部世界的变化转成一次出口选择。例：GitHub webhook、cron、文件 watch。
工作节点 worker
有进有出的节点。接任务、跑能力、跑完选一个出口。例：机器上的 review、implement。
终端 / 叶子 sink
只有入口、没有出口的节点。收了活就结束。例：推手机、写日志。
节点池
两级：nodes 管身份与配额，node_instances 管执行器与并发。一台机器一份身份、多个实例。
凭据与标签
节点用 token 注册，标签由中枢赋值、不接受自报。token 泄露 = 继承该节点全部标签，这是必然代价。
下线分级
节点消失时按 idempotent / resumable 决定：只读的放弃，有副作用的告警等人工，可续传的换节点重派。
粘性 sticky
能力是否要求固定实例（共享工作目录、增量编译）。默认关闭——结果存在中枢，下游不需要回原机器。
落点表 node_pins
粘性路由的查表结果。只在能力声明了 sticky 时才写入和查询。
sticky_key
由 trace、能力、选择器三段算出的哈希。只在 sticky 开启时使用。
最少负载优先
默认派发策略：在标签命中的实例里比 inflight / concurrency，取最小的。全满就排队，不溢出到不匹配的节点。

能力与出口

能力 capability
节点申报的「我能做什么」。路由的单位是能力，不是机器。一台机器可以申报很多个。
出口 output / port
能力的命名出口。跑完之后节点选择走哪个。它是字符串，不是条件。
边 edge
(from_capability, from_port) → to_capability 的三元组，路由表的一行。
出口表 edges
全部边的集合，中枢侧唯一的路由依据。没有 match、没有条件树、没有优先级、没有表达式引擎。
派发 dispatch
查 edges 表，返回 N 行就建 N 个任务。全部下发，不择一。
扇出
一个事件引起多个任务。本期无条件支持，N 是多少不管。
收集 / join
等一组任务齐了再触发下游。本期不做，需要时放在节点内部实现。
接力
任务结果变成新事件，再查一次 edges 表，生出下一跳。
回报 report
节点跑完提交 {status, out}。out 是出口名或 null。
出口名 out
节点在 result 里回报的出口选择。一个字段表达两件事：有没有下游（null）、有哪个下游（具体值）。它和 status 正交。
行程 path
从根到本任务这条具体路径的能力名序列，不是整个 trace 见过的集合。两条分支互不影响。
剪枝 pruned
因行程里已有该能力而不建任务。静默但不隐形成：trace 上记原因。
环
允许。图是显式声明的，所以配置期就看得见。运行期靠行程去重保证终止，max_hops 只是外显上界。
落定 settled
没有在跑的任务、没有未到期任务、每个终态任务都已回报出口。三者缺一不可。
接力开关 allow_chain
闸 G1。不显式打开就绝不接力。默认关，不可配。
深度上限 max_hops
闸 G2。一条链最多走到第几跳。默认 10，硬顶 32。
任务上限 max_tasks
闸 G4。一条 trace 最多建多少任务。默认 100，硬顶 1000。超出记 pruned。

任务

任务 Task task
「让某台机器做一件事」的意图加它的执行状态。machine sink 的最小调度单位。
任务 id tsk_
任务 id 前缀，值同时充当该任务的 span_id。trace 上看到的每个任务 span 都有对应的 tsk_ 行。
幂等键 idempotency_key
去重键：同一个 key 的重复投递应当只落一个任务。本期范围里没有定义这个字段，重复触发就是重复任务，防重复靠收紧 match 加 daily_budget 兜底。
状态 status
九态状态机里的当前值，是唯一能回答「这个任务卡在哪」的字段。
九态状态机
pending → assigned → acked → running → succeeded / failed / canceled / abandoned，另有 lease_expired 中间态。中间态不是终态。
租约到期 lease_until
这个任务被某节点占用的截止时刻。心跳每 10s 把它推到 now + 30s；心跳停了就是失联。
lease_expired
租约失效的中间态。attempts 没用尽就回 pending 重派，用尽则 abandoned。
接单 ack
接单确认，不是完成。节点说「这单我接了」，租约才正式计时；结束只看 result 事件。
attempts
中枢派发次数，租约回收也算一次。上限 3，退避 10s → 60s → 300s。
internal_attempts
节点在机器上自己重试的次数，不消耗中枢 attempts。由 manifest.capabilities[].retries 约束。
结果 result
终态时节点回报的内容，上限 8KB。更大的输出留在节点本地，回执只带截断后的结果和本地日志位置。
放弃 abandoned
不重试、必通知。不等于成功，也不等于静默丢弃；和 failed 的区别正在「不重试」。
生命周期 lifecycle
能力可声明四项：expiresInSec 硬过期到点即放弃绝不重派 / retryable 是否允许中枢重派 / maxAttempts 重派上限 / resultTtlSec 到期只清 result 不清行。

运行时

节点 Node node
身份（脑）：一个 node_id、一份凭据、一组中枢赋值的标签，以及它声明过的命令名。并发瓶颈在它这一层。
实例 NodeInstance node_instance
执行器（手）。一台机器可以跑多个实例，各自申报 concurrency / inflight / status。
能力清单 manifest
节点上报的「声明了哪些命令名」。只报名字和参数形状，不含 argv 原文，也不报版本号。
参数表 commands[].argv
命令的真实参数数组，写在节点本地 ~/.anotifyd/config.yaml，永不上传。
execve
唯一执行方式：拿 argv 数组直接 exec，不经 shell。禁止 /bin/sh -c，所以参数不会被二次解析。
unknown_action
收到自己表里没有的命令名时的回报。中枢不猜、不改写、不换成别的命令重试。
命令并发 concurrency
命令级并发上限，节点本地声明。实际并发取三层上限的 min。
在跑数 inflight
实例当前正在跑几个任务。派发按它做「最少负载优先」。
max_concurrency
节点级并发上限。三层取 min 的最后一道，防止单个节点被一个高峰吃满。
max_instances
一个节点允许跑几个实例，默认 20。防的是凭据扩散：每个实例一份 token，越多越难收。
落点表 node_pins
粘性路由的查表结果。首次选完写进去，之后同一 key 一律查表，不重新算。
sticky_key
由 trace、能力、选择器三段算出的哈希。只在命令声明了 sticky 时使用；默认派发不查这张表。
粘性 manifest.capabilities[].sticky
命令是否要求固定实例（共享工作目录、增量编译）。默认关闭——结果存在中枢，下游不需要回原机器。
出口申报 terminal
命令自己声明「没派生后续时算不算走完」，默认 false（保守）。收敛判定只认这个，不从命令输出反推。
幂等 idempotent
命令是否只读无副作用，默认 false。它决定节点下线时任务怎么收场：true 直接放弃，false 放弃加告警加人工确认。
可续传 resumable
命令是否支持断点续传。true 时节点下线可重派到新节点，从中断点继续。

安全与限额

闸 G1
allow_chain：不显式开启就不接力。默认关，不可配。
闸 G2
max_hops：深度上限，默认 10，硬顶 32。
闸 G3
环检测：path 里 rule_id 去重。隐含生效，不可配，也是终止性的真正来源。
闸 G4
max_tasks：单个能力单 trace 的任务数上限，默认 100，硬顶 1000。
闸 G5（已废弃）
付费任务数。已从设计里删掉，任何新配置都不该再引用这个编号。
闸 G6
max_duration：单 trace 总时长上限，默认 24h，硬顶 7d。
硬顶
写在代码里的上限，配置只能往下改不能往上改。改硬顶等于改代码加发版，不走配置。
三层覆盘
同一类限额的三层配置：全局 env → 单个能力 → 代码硬顶。前面两层可改，最后一层只能改代码。
派生凭据 jti
派生 JWT 里的一次性 id。claim 还含 trace / span / hop / maxHop / branchBudget / exp，跳数由中枢签发，节点改不动。
branch_nonces
已消费 jti 的表。消费 jti、建任务、扣额度在同一个事务里，重放直接失败。
branchBudget
本次派生还剩多少额度，由节点自主分配。额度用尽必须可见，绝不静默失败。
budget_exhausted
额度用尽的三件套：返回 409、span 上写一条 event、控制台标注。少一件就等于静默失败。
凭据 token
节点唯一凭据，一一对应一个 node_id。泄漏即继承该节点全部标签，这是已知代价；可撤销后重发。

版本

graph_versions
图配置的版本表（edges + capabilities），append-only：改一次加一行，旧行不覆盖。trace 钉的是这里的 id。
node_manifest_versions
节点能力清单的版本表。节点不报版本号，中枢按内容算哈希得到版本，所以「声称的能力」和「实际内容」不会分叉。
registry_versions
命令注册表（命令名到参数形状）的版本表。中枢只知道名字，形状的变更也要钉版本。
content_hash
版本内容规范化后的哈希，带唯一约束。内容没变就不产生新版本，版本膨胀被挡住。
版本 id 格式
<prefix>_<UTC>_<hash8>，例如 reg_20261023T101500Z_a1b2c3d4。人眼能看出时间和前缀，机器能校验前八位哈希。
叠加图 overlay
把「配置了什么」和「实际走了什么」叠在一张图上的视图。亮实线 = 走过，灰虚线 = 配了没走，红虚框 = 剪枝。

sink

human sink
推手机。尽力而为、可丢、不回报结果，没有租约也没有重试。
machine sink
node agent。至少一次、有租约、有重试、有 DLQ，而且必须回报。两类 sink 永不混用。
死信 DLQ
machine sink 重试耗尽的投递落到这里等人工看，不静默消失。这就是 machine sink 必须回报的代价，也是它跟 human sink 最硬的分界。
四个「没做成」别混。pruned 是任务压根没建（条件成立但被环/深度/预算/时长挡下）；suppressed 是本来要发的没发； failed 是跑过但失败、可重试；abandoned 是不再重试且必须通知。混用任何一个，事后就再也解释不清「这次为什么没发生」。

前缀速查

id 前缀一眼就能看出对象类型。标「本期不用」的，是这个前缀没有对应的对象——不是还没写，而是设计上就不需要。

前缀 代表 说明
evt_ 事件 event 外部触发与任务结果回流都用它，事件只追加不修改。
trc_ 链路 trace 本期不用：没有独立的 trace 行，链路是按 trace_id 把事件和任务聚合出来的。
spn_ span 本期不用：span_id 就是 task.id，走的 tsk_ 前缀。
tsk_ 任务 task 任务 id，与 span_id 同值。trace 上的任务 span 就是它。
grf_ 版本 graph_versions（图：edges + capabilities） 图版本，格式 grf_<UTC>_<hash8>，append-only。
nmf_ 版本 node_manifest_versions 节点能力清单版本，由内容哈希算出，不由节点自报。
reg_ 版本 registry_versions 命令注册表版本，例 reg_20261023T101500Z_a1b2c3d4。
inst_ node_instances 执行器实例，一台机器可以有多个。带 concurrency 与 inflight。
fan_ 扇出批次 本期不用：没有「批次」这个对象，扇出只是一次 INSERT 多建几行任务，不需要批次 id。
