# Anotify · UI/UX 全面评审（2026-11-13）

> **性质**：只读审计。本文档不改任何代码、不改 CSS、不改 i18n。
> **范围**：`web-src/pages/*.html` 19 页 + `web/tokens.css` + `web/ui.css` + `web/partials.js`。
> **方法**：`make mock` 起真实 DOM/CSS（假数据）→ 无头 Chromium 抓 **19 页 × 暗/亮 × 1440/390 = 106 张全页截图** → 逐张看图 → **12 路并行只读侦察**（分 4 批：IA / 交互摩擦 / 设计系统 / 响应式+a11y / 历史决策 / 首跑旅程 / 对比度 / 文档页 / 规模化 / 逐页高度 ×2 / 改动落点）交叉验证。
> **证据目录**：`.pi-orchestrator/out/ui-review-2026-11-13/`
> `shots/` 是 10 张细部裁剪图，`full/` 是 106 张全页图 + `metrics.json`（每页高度/横向溢出/触控目标计数）。
> **复跑**：`NO_TUNNEL=1 make mock`（7788）→ `node /tmp/ui-shots/shoot.mjs`。

## 0. 摘要

**底子好，精致度差最后一层。** 问题集中在三处，而不是零散的审美偏好：

1. **容器没有层次**——暗色卡片 vs 页底只有 **1.055:1**（ΔL* 2.62），亮色下侧栏与卡片 **同为 `#ffffff`**（`tokens.css:180/181`，对比度 1.000）。所以页面读起来是"一片"而不是"若干块"。这是"不够精美"的最大单因。
2. **产品里混进了工程内部**——`resourceVersion（CAS 令牌）`、`targetsResolved`、`sha256` 指纹、`slot 0 · 占用…`、`deliveryId`、`configRevision` 直接上屏；源/节点/任务页的主内容是裸 JSON。
3. **每个动作都给了 3~5 个平行按钮**——全站 63 处 `btn-primary`（security 8 / cli-auth 7 / login 7 / capabilities 6），源行 5 个动作按钮，安全页同一个"添加 Passkey"有三个入口。
4. **手机端是"缩小版桌面"**——9 个页面存在必须横滚才能读完的主内容（keys 表 2.01×、链路图 3.6×、docs 代码块 2.7×），主操作按钮统一 **30px 高**（低于 44dp），输入框 12.8~14px 会触发 iOS 聚焦自动缩放。详见 **§7 专项**。

**如果只做三件事**（按性价比排序）：

| # | 动作 | 影响面 | 成本 |
|---|---|---|---|
| 1 | 卡片层次拉到暗 1.25~1.35:1 / 亮色加边框+微阴影 | 全部 19 页 | 改 6 个 token + 1 个 `.card` 规则 |
| 2 | 每页只留 1 个 `btn-primary`，其余降级；内部字段进"开发者信息"折叠 | 全部页面 | 纯前端，不动 API |
| 3 | 首页去掉空 spark 虚线、图卡高度贴合内容 | 首屏观感 | 改动集中在 `index.html` |

## 2. 视觉诊断：8 个跨页根因

### 2.1 容器层次 = 1.05:1（量化）

| 配对 | 主题 | 对比度 | ΔL* | 证据 |
|---|---|---|---|---|
| `--surface-1` 卡片 vs `--bg-raise` 侧栏 | **亮** | **1.000:1** | 0.00 | `tokens.css:181` 与 `:180` **同为 `#ffffff`** |
| `--surface-1` vs `--bg` 页底 | 暗 | **1.055:1** | 2.62 | `tokens.css:29,31` |
| `--surface-2` 表头 vs `--surface-1` 行 | 暗 | 1.045:1 | 2.24 | `ui.css:3039` vs `:3017` |
| `--line` 描边 vs 卡片 | 暗/亮 | **1.18:1** | — | `tokens.css:34/184` |
| `--line-strong` 强边框 vs 卡片 | 暗/亮 | 1.47 / 1.37 | — | `tokens.css:35/185` |

非文字边界的可用阈值是 3:1，实际"能分出块"的经验阈值 ≥1.3:1。**当前全部低于阈值**，只有阴影（`--shadow-1`）在暗色下勉强托住卡片。

### 2.2 首屏强调面过密

- 首页首屏：1 个主 CTA + 4 张 KPI（各 1 个 accent 底图标 + 1 个 delta 药丸 + 1 条 accent spark）+ 热力图 4 级 accent = **≥9 个品牌色强调面**。
- `security.html`：8 个 `btn-primary` + 9 个彩色徽章 + 8 个带光晕的 dot；`capabilities.html` 6 个 `btn-primary`。
- 全站 `btn-primary` 计数：security 8 / cli-auth 7 / login 7 / capabilities 6 / passkey-enroll 5 / receivers 5 / keys 4 / nodes 4 / playbooks 4 / sources 3 / node 2 / playbook 2 / source 2 / events 1 / index 1 / message 1 / trace 1 / admin 1 / docs 0 —— **合计 63 处（另有 1 处在注释里），其中 14 处是 JS 动态生成的**。

### 2.3 "看起来坏了"的空数据占位

6 张 KPI 卡**全部**带 `.stat-spark` 容器，但只有 `kpi-total` / `kpi-today` 有日序列（`data-spark-scope="events"`），其余 4 张恒为空 → JS 打上 `is-baseline`（`index.html:1244-1253`），CSS 画成 **5px/5px 虚线**（`index.html:348-355` 的 `repeating-linear-gradient`）。

一屏 4 张卡里 2 张有曲线、2 张是虚线 → 用户第一反应是"数据挂了"。

### 2.4 大面积"空容器"

- 链路图：`.flograph--silk` 的高度是 `clamp(480px, 64vh, 880px)`（`ui.css:4544`），运行时又被 JS 覆写成 `min(need, max(baseH=480, 560))`（`web/flograph.js:2518-2530`）。`need = contentH + 39 + 35 + 2`，节点行本身只有 ~40px 高 → **上下各余 ~100px 空白**（见 `shots/03-index-flow-dark.png`）。
- 登录页左卡：品牌区 ~220px 空白，底部孤零零一行"无第三方账号"（`shots/` 未收录，见 `full/login-anon-d-dark.png`）。

### 2.5 页面标题两套字体

`index / events / message / trace` 的标题叠 `.font-display`（Fraunces 衬线，`ui.css:25`），`keys / sources / nodes / security` 是 Inter 600（`ui.css:2735`）——同一级标题两种气质。品牌字标 "Anotify" 用连笔手写体，与几何无衬线正文也不同源。

### 2.6 JSON 当主视觉

| 页面 | 首屏第一个内容块 | 高度 |
|---|---|---|
| `source.html` | `payloadSchema` JSON textarea | ~250px |
| `node.html` 左栏 | namespaces / vars / limits **三个** JSON textarea | ~360px |
| `trace.html` | 事件事实 3 块裸 JSON | ~1000px |
| `message.html` | 参数 JSON + 结果 error JSON | ~300px |

且 `source.html` 把同一份关系画了两遍：`目标能力 targets`（JSON）+ `只读 v4 目标能力投影`（又一份 JSON）。

### 2.7 组件语汇各页自成一派

| 组件 | 套数 | 证据 |
|---|---|---|
| 药丸 | **7 套**（0.65/0.66/0.68/0.7rem/12px + 3 档圆角） | `.tag-chip` / `.kbd` / `.src-*` / `.pb-badge` / `.status-badge` / `.out-chip` / `.badge` |
| Tab | 4 套尺寸 | `.tab` / `.channel-tab` / `.filter-tab` / `.seg-item` |
| 按钮 | 5 变体 + 7 个页面级修饰符；`.btn-primary` 有两份定义 | `ui.css:423` 与 `:2943` |
| 卡片内距 | 3 档（20 / 24 / 14+16） | `.card-pad` / `.state-card` / `.doc-step` |
| 页面私有状态类 | 19 个 `is-*` | 与 `.badge-*`/`.status-*`/`.dot-*`/`.st-*` 四套语义命名并行 |

内联页面 CSS **5639 行**，已经超过 `ui.css` 的 5575 行；页面自定义类 668 个 > ui.css 438 个。

### 2.8 深浅色只换颜色，不换层级

- 亮色下白卡浮在 `#f7f8fc` 上（1.061:1），描边 1.18:1 → 卡片几乎不可见。
- 亮色下 `--bg-raise` 与 `--surface-1` 完全同值，侧栏与卡片没有分界。
- 亮色 KPI 卡的 `Header: Authorization` 块是淡紫，读起来像"被禁用"或"被选中"。

### 3.1 总表

| 页面 | 观感分 | 最刺眼的一点 |

| 预案详情 | 3.5 | 失败后徽章卡在"正在读取…" |
| 任务详情 | 3 | 2359px 高，前 200px 没有结论 |
| 能力 | 3 | 8 行里 7 行"未就绪"，4 个实心药丸/行 |
| 节点 / 节点详情 | 2.5 | sha256 指纹、槽位调试串上屏 |
| 事件流 | 2.5 | 每条 197px（手机 340px），双 ID 并列 |
| 源 / 源详情 | 2.5 | 5 个按钮 + 两份同义 JSON |
| 预案列表 | 2.5 | 双空态 + 常驻导入表单 |

| 管理后台 | 2.5 | 4 张 0 值卡；两列同样的绿药丸 |
| 通知接收 | — | **侧栏无入口，全站孤儿页** |

### 3.2 详述（按修复价值排序）

**① 总览（index）**
- 2 张 KPI 虚线（§2.3）。
- 热力图 53 周 × 7 行 = 371 格，为 4 条事件服务，占首屏 ~200px；`近 30 天 4 条事件 · 活跃 1/30 天` 与 KPI 重复。
- 「最新事件链路」右侧第 4 个节点被卡片边缘切掉，唯一提示是 10px 灰字"← 可横向拖动 →"。
- **`#flow-host` 多带了一层 `overflow-x-auto`**（`index.html:694`），而 `trace.html:321-324` 的注释明确说"容器不再带 overflow-x-auto：flograph 已经在 `.flograph-scroll` 里自己做横向滚动" → **首页与链路页的滚动容器不一致，首页多一层嵌套滚动（手势冲突 + 双滚动条风险）**。
- 事件流列表三段式（chip 左 / id 中 / 时间右），中间大片留白。

**② 事件流（events）**
- 四列 label/value 常驻；**同时暴露 `事件 UID（非 deliveryId）` 与 `deliveryId`**。
- 筛选面板 4 字段常驻首屏上方，手机占 330px。
- 每条事件行高，桌面约 197px、手机 ~340px（7 行堆叠）。
- `dispatched` 是裸 JSON 文本，**没有任务链接**（`trace.html` 已有 `taskLink()` 可复用）。

**③ 源 / 源详情**
- 列表每行 5 个动作：编辑 / 停用 / 删除 / **已保存源试运行** / **立即运行**（后两者对非作者不可分辨）。
- 详情页 5 个按钮在 390 下折成 3 行（`shots/06-source-actions-dark.png`）。
- `resourceVersion（CAS 令牌）31`、`targetsResolved（布尔）`、`targets 已解析` 上屏。
- 副标题「源产生事件；目标能力接收参数。**配置图不是执行成功的证明**。」= 设计旁白。
- `targets` 画两遍（§2.6）；Hook URL 无复制按钮。

**④ 能力（capabilities）**
- 8 行里 7 行带琥珀 `未就绪`；每行 4 个实心药丸（实现/节点可用/下游可解析/已部署）→ 整页读成"处处告警"。
- 新建能力要 15+ 字段含 3 个手写 JSON/脚本块；而 `/v1/capability-templates` 后端已实现、**前端 0 引用**。
- 行内 24 个元素、1 个按钮（结构本身不差），问题在色彩语义。

**⑤ 节点 / 节点详情**
- `已应用哈希 sha256:93703c…`（两个 64 字符）+ 5 个能力部署指纹上屏；`slot 0 · 占用（运行、预留或回收中）· task=tsk_mock_2 · id=nins_mock_1` 是调试串。
- 三列配置版本（配置版本 8 / 已应用版本 7）这种**漂移**是重要状态，却与普通文本同一样式，没有视觉警示。
- 左栏 3 个 JSON textarea 与右栏 limits 表格**重复同一份数据**。
- 下半页「命名空间 vars 配置」「系统保留配置（管理员）」两张大表单对 90% 用户是噪音，文案是给维护者看的。

**⑥ 任务详情（message）**
- 2359px 高，前 200px 是 8 个键值对（尝试/上限、configRevision、digest…），结论"已派发 2 条下游"埋在中段。
- 徽章写成「成功 · succeeded」（中英双语同一意思）。
- 日志错误直出 `载入失败：请求被拒绝 HTTP 410` + 英文原文，中英混排。
- `放弃任务`（危险）与 `取消任务` 同为次级按钮。

**⑦ 链路（trace）**
- 图区域是页内最好看的部分；下面「任务 / 尝试 / 等待诊断」是扁平信息堆（每行：名 + 序号 + id + 徽章 + 尝试 + parentTaskId + 结果），无层级。
- 事件事实 3 块 JSON 占 ~1000px；`剪枝原因` 在页尾。

**⑧ 预案（playbooks / playbook）**
- 空态卡 + 常驻导入表单同时存在；页头"导入安装包"、空态"立即导入"、表单"保存安装包"是同一件事三个入口。
- 导入表单 5 种输入方式（select / 包名 input / 文件 / 目录 / JSON textarea `{}`）。
- **失败态 bug**：`#pb-badge` 的"正在读取…"只在成功路径被改写（`playbook.html:317`），404/409 时永久停在"正在读取…"，并留下一个空圆角容器（`shots/` 见 `full/playbook-detail-d-dark.png`）。
- 409 重名被渲染成"载入失败：请求被拒绝 HTTP 409"。

**⑨ 安全与登录（security）**
- 同一个"添加 Passkey"三个入口：页头「+ 本机添加」、「⇄ 在新设备添加」、空态内「+ 本机添加」，且文案教用户"点右上角「+ 本机添加」"。
- 空态标题与正文重复同一句。
- 8 个 `btn-primary` + 9 个彩色徽章 + 8 个光晕 dot 同屏。
- 页尾「两条独立的轴」是架构课，占 ~200px。

**⑩ API Keys**
- 「上报接口」两个框看起来像 disabled input（亮色下尤其）。
- 「Key 的安全实践」4 条常驻，且用警示琥珀三角做装饰。
- 操作列只有红色文字"停用"，危险动作与正文同级。

**⑪ 管理后台**
- 4 张 KPI：用户 3 / 消息 0 / 设备 0 / 送达率 0%，三张 0 值卡占满首屏。
- 「超管」「正常」两个绿药丸并排；自己那行操作列显示"你"。
- 底部「管理后台能做什么」3 条说明里 `(401)` 折行。

**⑫ API 文档**
- `#endpoints` 一节 = 全页 **45.2%**（125 个端点 / 21 张卡 / 1222 个 DOM 行），而 `#auth` 只有 32 行 → 单节体量差 38×。
- **全页 0 个 `<h1>`**：页标题 `h2.page-title` 与 7 个章节 `h2.doc-h2` 同级；`#node` 的子标题是 `h3` 但套 `.doc-h2` → 字高 24px 与 h2 完全一致。
- 7 个 h2 的 `margin` 全为 0，与下文距离由兄弟决定 → 全页并存 **0 / 10 / 14 / 16px 四种值**；`#node` 内两处 0px（代码块紧贴说明、note 紧贴 h3）。
- 390 宽下代码块可视 318px ≈ 42 字符，最长命令 ~120 字符 → **需 2.8× 横滚**，7 块里至少 5 块必然横滚。

**⑬ 登录 / CLI 授权 / Passkey 登记**
- 登录默认 tab 是"登录"，新用户得自己发现"注册"。
- 三个登录入口（Passkey 大按钮 / 居中文字"用密码登录" / 底部"用恢复码登录"）层级不清。
- 恢复码弹窗是唯一一次明文，**没有"我已保存"勾选**（API Key 页有）。
- `#code-input` 无 label / 无 aria-label，仅 placeholder（`cli-auth.html:480`、`passkey-enroll.html:440`）。

## 4. 交互与流程

### 4.1 横切事实（逐页问题大半由它们产生）
