## 问题

真实租户到 50~200 条时，列表页是"9~36 屏的长条 + 一万个 DOM + 一个搜索框都没有"。mock 只有 2~5 条所以看不出来。

## 范围 / 落点

**后端 / 契约**
- `api/resource.yaml`、`api/auth.yaml`：给 8 个列表接口加 `limit` + `continue`（复用 `LimitQuery`/`ContinueQuery` 定义 `resource.yaml:1348-1361`）
- `internal/server` 对应的 list handler 与 `internal/store` 查询

**前端**
- `web-src/pages/{sources,playbooks,nodes,keys}.html`：加搜索框（capabilities 可参考 `capabilities.html:568` + `:2363`）
- 统一"20 条 + 加载更多"，不再一次渲染全量

## 验收

- [ ] 8 个接口支持 `limit`（缺省 50）+ `continue`，越界/非法参数行为与既有 `LimitQuery` 一致
- [ ] `api/*.yaml` 与实现一致，`python3 scripts/check_openapi.py` / `check_contract.py` 通过
- [ ] sources / playbooks / nodes / keys 四页有搜索（本地过滤即可，先不要求服务端搜索）
- [ ] 列表首屏渲染 ≤20 条；「加载更多」按 20 递增；200 条时 DOM 元素数不随总条数线性增长
- [ ] e2e：新增"50 条数据下翻页"用例；现有断言不因分页失效
