## 现状（按当前代码）

| 页面 | 首屏第一个内容块 | 高度 |
|---|---|---|
| `source.html` | `payloadSchema` JSON textarea | ~250px |
| `node.html` 左栏 | namespaces / vars / limits **三个** JSON textarea | ~360px |
| `trace.html` | 「事件事实」3 块裸 JSON | ~1000px |
| `message.html` | 参数 JSON + 结果 `error` JSON | ~300px |

重复渲染的具体例子：

- `source.html` 把同一份关系画了**两遍**：`目标能力 targets`（JSON）+ `只读 v4 目标能力投影`（又一份 JSON）
- `node.html`：左栏 `limits` textarea 与右栏 `limits` 表格是同一份数据

## 问题

用户是来看"这个源会派给谁 / 这个节点跑什么 / 这次执行为什么失败"的，不是来看 JSON 的。JSON 当主视觉会同时造成：首屏被占满、关键信息被埋、手机上必须横滚（见 mobile 相关 issue）。

## 范围 / 落点

- `web-src/pages/source.html`：`payloadSchema`、`targets`、`只读 v4 目标能力投影`
- `web-src/pages/node.html`：`#node-namespaces` / `#node-vars` / `#node-limits`
- `web-src/pages/trace.html`：`#trace-events` 三块
- `web-src/pages/message.html`：`#task-params`、`#task-result`

## 验收

- [ ] 上述 4 处默认呈现为**结构化视图**（键值表 / 目标能力列表 / 参数表单），JSON 改为「查看原始」折叠（默认收起）
- [ ] 同一事实只渲染一次（删掉 `只读 v4 目标能力投影` 或与 `targets` 合并；limits 二选一）
- [ ] 编辑场景不受影响：节点配置仍需可编辑（textarea 可保留，但默认收起并在摘要里给出"3 项 / 2 项"这类概览）
- [ ] `trace.html` 首屏能看到"哪一步失败 / 剪枝原因"，不必滚过 JSON
- [ ] e2e：`#trace-events` / `#task-params` 等锚点保留（可改为折叠内的容器）
