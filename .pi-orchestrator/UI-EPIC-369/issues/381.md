## 现状（按当前代码）

**1) `receivers.html`（通知接收）是孤儿页**

- `web/partials.js:163-243` 的 `NAV`（8 项 / 2 分组）**没有 receivers**
- `web-src/pages/receivers.html:645-648` 仍传 `active:"receivers"` → 侧栏零高亮、顶栏拿不到分组名
- 全站唯一命中：`web-src/pages/login.html:1229` 的 redirect 白名单、`web/partials.js:1984`
- 该页首屏显示「推送暂未开放」（`PUSH_UI_ENABLED=false`，`web/partials.js:2412`），且 `index.html` 已据此隐藏「接收设备 / 送达率」两张 KPI

**2) 首跑旅程在 v4 无法在纯 UI 内闭环**（7 步）

1. 登录页默认 tab 是「登录」，新用户要自己发现「注册」（无"实例无用户 → 默认注册"分支）
2. 恢复码弹窗是唯一一次明文，**没有"我已保存"确认**（API Key 页有）
3. 落到首页：4 个 `–` + 空热力图 + 空链路，主 CTA 指向 `docs.html#agent`（`index.html:369`）
4. 侧栏找不到「接收」
5. 登记节点后，示例命令 `anode emit fixer --id review-a.go`（`nodes.html:109`）引用**新实例不存在的能力**
6. 装完节点"没有任何能力可跑"
7. `PUSH_UI_ENABLED=false` → 收不到通知

## 问题

用户按导航走完全程也到不了"接收"；首页没有"从 0 到第一条事件"的路径。

## 决策点（需先定，二选一）

- **A**：给「通知接收」一个正式入口（`NAV` 加项，或在「安全与登录」里并入"投递"分区）
- **B**：推送未开放期间把该页下线（路由 404 / 隐藏），等开放再上线

## 范围 / 落点

- `web/partials.js:163-243`（NAV）、`:1080-1085`（`NAV_GROUP_OF`）
- `web-src/pages/index.html:360-376`（首页 CTA 与摘要）
- `web-src/pages/nodes.html:96-110`（令牌面板里的示例命令：`emit fixer` 改成真实存在的能力，或给出"先建一个能力"的链接）
- `web-src/pages/login.html`（首跑：无用户时默认注册 tab）
