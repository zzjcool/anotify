## 现状（390 实测）

| 规则 | 字号 | 证据 |
|---|---|---|
| `.input` | `0.875rem` = **14px** | `web/ui.css:554` |
| `.select` | `0.8rem` = **12.8px** | `web/ui.css:589` |
| `.textarea` | 14px（继承 `.input`） | 同上 |

受影响输入共 **21 个**：

```
events    #ev-namespace(12.8) #ev-source(14) #ev-trace(14) #ev-limit(12.8)
nodes     #config-namespace(12.8) #namespace-vars(14) #result-ttl(14) #event-ttl(14) #task-ttl(14)
node      #node-namespaces(14) #node-vars(14) #node-limits(14) #node-namespace(12.8)
message   #logs-previous(14) #logs-tail(14) #logs-since(14)
capabilities  #caps-search(14) #caps-filter(12.8)
playbooks     #pb-input-kind(12.8) #pb-input-name(14) #pb-input-files(14)
```

iOS Safari 规则：输入框 `font-size < 16px` 聚焦时**自动 zoom**，且失焦不会缩回 —— 每次点进筛选/节点配置/日志参数，页面都会"跳"一下。当前 viewport meta 没有 `maximum-scale`（这点是对的）。

## 范围 / 落点

- `web/ui.css:554`、`:589`（以及 `.textarea` 若单独定义）
- 建议做法：移动断点内统一 `font-size: 16px`（或 `max(16px, 0.875rem)`），桌面保持现状
- **不要**用 `maximum-scale=1` / `user-scalable=no` 绕过（会伤害 a11y）

## 验收

- [ ] 390 与 360 下所有 `input/select/textarea` 计算字号 ≥16px（用脚本断言，附输出）
- [ ] 桌面端字号不变（回归截图）
- [ ] viewport meta 不含 `maximum-scale` / `user-scalable=no`（三个 layout 都检查）
- [ ] 真机 iPhone 验证：聚焦 `#ev-source`、`#namespace-vars`、`#logs-tail` 不触发页面缩放
