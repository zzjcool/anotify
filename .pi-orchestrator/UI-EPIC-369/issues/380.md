## 现状（按当前代码）

`playbook.html` 的标题旁徽章是**静态渲染**的：

```html
<span id="pb-badge" class="badge badge-neutral">{{t "pb.v4.loading"}}</span>   <!-- playbook.html:130 -->
```

只有成功路径会改写它：

```js
$("pb-badge").textContent = t(status.ready ? "pb.status.ready" : "pb.v4.not_ready");
$("pb-badge").className = "badge " + (status.ready ? "badge-success" : "badge-warn");   // :317-318
```

`status` 只在载入成功后才会被调用 → **404 / 409 / 网络错误时，徽章永久停在「正在读取…」**，且页面下方残留一个空的圆角容器。

实测：`full/playbook-detail-d-dark.png`（mock 里 `?id=nightly` 返回 404）——同一屏上同时出现「正在读取…」和「载入失败：请求被拒绝 HTTP 404 / Playbook 不存在」，互相矛盾。

## 问题

状态自相矛盾：标题说还在读，正文说读失败了。用户不知道该等还是该重试。

## 范围 / 落点

- `web-src/pages/playbook.html:130`（初始徽章）
- 载入失败分支（`loadErrorNode` 调用处，约 `:493` 的 `if (!name) throw` 与 catch 段）：把徽章置为 `badge-error` + 「载入失败」
- 失败时移除/隐藏数据容器（当前残留的空圆角块）

## 验收

- [ ] 404 / 409 / 500 三种失败下，徽章显示「载入失败」（`badge-error`），不再出现「正在读取…」
- [ ] 失败态页面不再残留空的数据容器
- [ ] 成功路径徽章行为不变（就绪 / 未就绪）
- [ ] 新增 e2e：访问一个不存在的 playbook id → 断言徽章文案与 DOM（并断言空容器不存在）
