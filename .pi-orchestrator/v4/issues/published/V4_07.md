## 已知风险与所需产出
1. strict Open 目前校验列/PK/FK/unique，不校验 CHECK：同列但丢关键 NULL-failed/normal-pin 约束的库可能被接受。定义可维护的关键约束校验，并测试旧/残缺库拒绝而不删除用户数据；不能仅宽松字符串搜索。
2. 未解析 failed/attempt0 行不能携带伪 result_accepted_at/Node过程/摘要结果等事实；补齐实际需要的 invariant guard/真实 SQL 阴性，不放松 normal Task pin/FK。
3. Emit planned prune 闭集与 Source 接收保持一致，`downstream_missing` 不得当 prune；非法/畸形 result receipt 明确拒绝，不能 JSON 解码失败后绕身份核对。
4. 当前部分 WS 阴性使用固定 sleep 后看0写：改为可证明 handler 已处理/有界同步后断言，不能慢机 handler 未跑即假绿。明确握手“旧HTTP no101”退役与 v4 hello fail-closed 的映射，不能过度声明。
5. 补真正 ctx 取消、无 emitId+prune失败 rollback、强制并发重复交错等有限覆盖。保原真实SQL trigger6点与回放原字节，不靠计数或 `-count100` 碰运气。
