### 实现裁决（文档留白处，请协调者/父会话确认或回写）
1. **体积超限码**：§9.2 无"文件太大"行，单文件 >2 MiB / YAML 合计 >8 MiB 统一报 `invalid_playbook`（消息点名文件 + 拆能力/拆包建议）。
2. **`status` 剥离落点**：`Package.Files` 保留上传原文（`includeBody` 是编辑/导出对象），**渲染时**剥离 `status`——这样"导入剥离"的语义落在渲染产物上，便于复查原文。
3. **源名正则**：source.md 未定义源名规则（store 只要求非空），包内沿用能力名正则 `^[a-z0-9][a-z0-9._-]{0,62}$`，`render_name_invalid` 才有判据（比 store 更严格，只在包路径上生效）。
4. **values 点号路径段字符集**：沿用 source.md §4.1（标识符或纯数字下标）。`{{values.a-b}}`、`{{ values.x }}`、`{{values}}`、`{{{values.x}}}` 一律**原样透传不报错**（§1.4「不检查残留」），`TestRenderValuesPathSyntax` 钉住。
5. **`next` 按集合比较**（顺序无关、重复无意义，边投影 to_ref 唯一）——行 7 判定与 store 写入口径一致。
6. **kind 差异**：`conflicts[].reason` 词表只有 `version_conflict`/`config_differs`，kind 不同报 `config_differs` + `fields:["kind"]`。
7. **两类冲突并存时的顶层码**：含源冲突 → `playbook_conflict`；只有能力同版冲突 → `version_content_immutable`。
8. **`no_node` note 不在 Plan 产出**（需节点池事实，属 §6 体检/派生 status → G3）；六个码的常量与 `NoteCodes()` 仍在此处封闭。
9. **`Plan` 拒绝 nil 快照**（防止"忘了传 = 以为库是空的"），空库用 `EmptyExisting()`。
10. **`InstallRef.At` 用 RFC3339 字符串**（store 落库是 unix 秒，落回执前 `time.Unix(...).UTC().Format(time.RFC3339)`）。
11. 入口 `apiVersion/kind` 允许省略、写了必须对（被引用文档同口径；值是模板时跳过判定）。
