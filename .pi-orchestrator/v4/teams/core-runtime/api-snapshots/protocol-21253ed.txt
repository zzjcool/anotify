package protocol // import "github.com/zzjcool/anotify/internal/protocol"

Package protocol 是 v4 节点协议（中枢 ↔ anode）的唯一类型源。

为什么单独一个包：帧、枚举、错误码、emit 网关 DTO、applied 文件形状都只能有
一份定义。中枢（internal/ws、internal/server）与节点（cmd/anode）都 import 本包， 禁止各自再写一份
snake_case / camelCase 的镜像类型——两份镜像第一次分叉时， 症状通常是「节点读不到中枢刚加的字段」，而两边都编译通过。

三条纪律：

  - 零本项目依赖：只用 stdlib（D-I10）。节点二进制不链 sqlite / server。
  - wire 字段一律 camelCase（docs/design/v4/api-conventions.md §3），帧类型名是
    文档里的点号名（task.dispatch / config.applied …），字符串本身是协议。
  - 无兼容层：v4 不提供 v3 帧别名。旧字段就是未知字段，解码时被忽略而不是报错 ——一条老帧不该因为多了一个退役的键就整帧被拒。

构造帧时，必填的列表/映射要给空值而不是 nil（空列表纪律：wire 上是 []，不是
null）。本包不做「自动补空」：帧的字段就是它声明的东西，隐式补全会让「节点没报」 和「节点报了个空」分不开。

帧集合 = 配置 5 帧（config.md §4.2）+ 执行 10 帧（capability.md §8.5）+ 保留的 运维 4 帧（upgrade
/ upgrade_ack / logs_request / logs_response）+ 人工部署 2 帧 （capability.deploy
/ capability.deployed，父 CONTRACT rev2 §7）+ emit 转发 2 帧 （task.emit 上行 /
task.emit.ack 下行，父 E1 批准）。

本包不含传输与会话状态机：ws 只做收发、心跳与背压；派发、租约、结果、emit 的 权威判定都在 route/store。emit 的有界等待 / 超时 /
迟到 ack 丢弃在节点网关， 本包只提供帧、字段校验与方向。

const (
	// FrameTaskEmit 是节点 → 中枢的 emit 转发请求（上行）。
	FrameTaskEmit = "task.emit"

	FrameTaskEmitAck = "task.emit.ack"
)
    emit 中转的 2 个 WS 帧（父 E1 批准，见 /tmp/anotify-v4-emit-ws-approval.md）。

    节点上的 HTTP emit 网关是本地入口（loopback / unix socket，Bearer attemptToken），
    它只做本地预检（目标是否在本能力 next 里、令牌是否还是本地记录的那一个）；**权威 判定在中枢**：中枢先验证连接节点身份、任务当前
    running、所属授权 namespace、 attempt / leaseId / attemptToken 与租约未过期，再在同一个事务/CAS
    边界里接受、 判 id 幂等并派发下游。所以能力脚本的一次 emit 需要一条「节点把同一个请求转给 中枢、再把中枢结论带回」的 WS
    通道，就是这两帧。

    纪律：
      - task.emit 的 to/id/data **匿名嵌入 EmitRequest**：HTTP 入口与 WS 转发只有 一份 payload
        解释（缺 target 仍是 HTTP 语义的 missing_target，不是另一种 payload 形状）。中枢据此复用
        EmitHTTPStatus / EmitExitCode，不造第二套码。
      - namespace 不在帧里：它由中枢按「任务的 namespace」与「节点申报 ∩ 授权」推导， 调用方不能通过 WS
        帧覆盖。requestId 只是一次 RPC 的关联 id，不是业务幂等键、 不是调用序号；跨 attempt 的业务判等只用显式 id（同
        task + 同 id）。
      - ack 只带关联身份（requestId/taskId/attempt）+ 结论，**不回显 attemptToken**， 也不回显
        leaseId：令牌不该被复制进第二条帧/日志。
      - 成功只有 response（含剪枝：taskId:null + pruned），错误只有 error；两者互斥。 没有 Status
        信封——本地 emit 不是资源 API，HTTP DTO 就是结论。

    有界等待/超时/迟到 ack 丢弃是节点网关的实现（N2 后续），不是这一包的运行器： 本文件只有帧、校验与方向。

	UpgradeErrNeedRoot       = "need_root"
	UpgradeErrBadSHA         = "bad_sha"
	UpgradeErrDownloadFailed = "download_failed"
	UpgradeErrNotSupported   = "not_supported"
)
    节点升级失败的判别短码（upgrade_ack.error）。

    它们会原样落库并出线给控制台，所以字符串是冻结契约的一部分。

const DefaultLimitsTotal = 1
    DefaultLimitsTotal 是 total 的缺省值（anode.md §2：缺省 1）。

const FrameSoftLimit = 1 << 20
    FrameSoftLimit 是逐帧软上限（1 MiB）。

    在 protocol 里定义而不是 ws：logs_response 的编码上限与它是同一个数，节点侧 必须在编码**之后**量字节数并截断（见
    LogsResponseMaxBytes）。两条常量分居两包 迟早会漂移，症状是「日志回包被当作超大帧拒掉」。

const LimitsWildcard = "*"
    LimitsWildcard 是 PerCapability 里「未单列的能力」那个键。

const LogsErrNoLocalArchive = "no_local_archive"
    LogsErrNoLocalArchive 是 logs_response.error 的唯一取值：这台节点上没有那次 执行的档案（被 GC 了 /
    老任务 / 不是这台机器跑的）。

const LogsResponseMaxBytes = FrameSoftLimit
    LogsResponseMaxBytes 是**一帧 logs_response 编码后**的上限。

    与 FrameSoftLimit 同值是刻意为之：服务端对超限上行帧的处置是先回 frame_too_large 再 1009
    关连接——一条「日志太大」把连接打断，比取不到日志严 重得多。所以节点侧必须自己先截断。

const NodeBinaryPath = "/v1/node/binary"
    NodeBinaryPath 是节点下载二进制的路径（GET 到中枢根上）。

    与 UpgradeFrame.URLPath 共用同一个常量：改路径只有一处，帧和 HTTP 路由不会漂移。

const NodeStreamPath = "/v1/node/stream"
    NodeStreamPath 是节点 WS 连接的路径（GET 升级到 WebSocket，拼在中枢根上）。

    与 NodeBinaryPath 并列：地址字符串是协议的一部分，节点与中枢必须用同一个常量， 不要在两侧各写一份字面量。中枢侧的空 path 或
    "/" 归一为本值；显式配置的 反代前缀原样使用（本常量只是标准默认值），不提供 legacy 别名。

func MachineConfigHash(vars map[string]string, limits Limits) (string, error)
    MachineConfigHash 是机器级配置（本机 ⊕ 节点默认值）的内容哈希。

    它只回答一个问题：「两台机器/两个时刻的**生效机器配置**是不是同一份」。 因此输入只有两样东西：

      - vars：机器级生效变量（local > node 合并结果）；
      - limits：机器级生效并发预算（local > node 逐叶合并结果，缺省 total=1）。

    明确**不包含** revision（版本号变化不代表内容变化）、namespace 默认值 （ns 级、随任务内存下发，不进
    applied）、token、宿主凭证、envPassthrough （完整名单只在本机，不上报）。两侧（中枢算期望值 / 节点算
    appliedHash） 只调用这一份实现，禁止第二份 hash 算法。

    归一化后取 canonical JSON（`vars` / `limits` 两个键，map 键由 encoding/json
    排序），SHA-256 输出 `sha256:<64 hex>`（与 artifact 的 digest 同前缀）。空 map 与 nil 一律写成
    `{}`；`limits.total` 未设置（0）归一为 缺省 1；`limits.perCapability` 同理缺省 `{}`。

    负的 total 不是「未设置」，无法归一成缺省值：返回 error（正常配置在 写入期就被拒，这里只是不静默吞掉非法输入）。

func NodeArtifactUploadPath(taskID, sha256 string) (string, error)
    NodeArtifactUploadPath 拼出上传路径（taskId 与 sha256 都做路径转义）。

    sha256 必须先过 ValidArtifactSHA256；不接受 "sha256:" 前缀（那是 spec digest 的形状）。

func NormalizeUpgradeError(code string) string
    NormalizeUpgradeError 把 ack 里的错误码收敛到契约枚举（未知码 → ""）。

    为什么不让未知码原样落库：出线形状是封闭集合（控制台按枚举做映射），存一个 UI 不认识的码只会显示「升级失败（未知原因）」；原始值已经进了 WARN
    日志。

func ParamEnvName(name string) string
    ParamEnvName 是参数名 → 任务环境变量名的归一函数（capability.md §2.3）： 全大写、非 [A-Z0-9] 的字符替换成
    '_'，**不插大小写边界**。

        sha       → ANOTIFY_PARAM_SHA
        repo-url  → ANOTIFY_PARAM_REPO_URL
        repoUrl   → ANOTIFY_PARAM_REPOURL
        参数      → ANOTIFY_PARAM__（每个 rune 一个 '_'）

    归一可能撞名（`sha` / `SHA` / `Sha`，`repo-url` / `repo.url`）：**撞名不在这里
    报错**，写入期由 artifact 用同一个函数检测并拒绝（param_env_collision）。 只有一份规则：artifact
    的校验与节点的注入必须调用本函数，禁止各写一份。

func PruneReasons() []string
    PruneReasons 返回全部剪枝观察原因（拷贝）。

func UpstreamFrames() []string
    UpstreamFrames 返回全部上行帧类型（拷贝，调用方可安全修改）。

func ValidArtifactLogicalPath(p string) bool
    ValidArtifactLogicalPath 校验托管逻辑路径。

    规则与 run.files 的相对路径同一取向：规范相对路径、`/` 分隔、无 NUL/反斜杠、 无空段 / "." / ".."、不以 "/"
    开头。它只是**逻辑名**，永远不能拿去拼宿主路径 （用户 workDir / 系统目录前缀都不允许出现在这里）。

func ValidArtifactSHA256(s string) bool
    ValidArtifactSHA256 报告 s 是否是 64 位小写十六进制（不带 "sha256:" 前缀）。

type CapabilityDeployFrame struct {
	Type string `json:"type"`
	// RequestID 是部署请求 id（中枢生成；回执按它配对，同一次重放保持同一个）。

	// DeployRefs 平铺为 namespace/name/version/digest。
	DeployRefs
}
    CapabilityDeployFrame 是中枢 → 节点的部署请求。

    它是在线节点上的一次显式人工部署；离线节点不靠这一帧，重连后由中枢重放 已请求的部署。**不带 Artifact 内容**（也没有 files 字段）。

type CapabilityDeployedFrame struct {
	Type string `json:"type"`

	RequestID string `json:"requestId"`
	// DeployRefs 与请求同一组 refs。
	DeployRefs
	// Status 是 applied（已获取、校验并缓存）或 failed。
	Status DeployStatus `json:"status"`

type CapabilityRef struct {
	// Name 是能力名（谱系，不是某个版本）。
	Name string `json:"name"`
	// Version 是解析到的版本号（省略 version 的能力由内容寻址分配）。
	Version int `json:"version"`
	// Digest 是部署身份（artifact.Digest），双保险：version 之外再钉一次内容。
	Digest string `json:"digest"`
}
    CapabilityRef 是任务钉住的目标能力（`{name,version,digest}`）。

    没有 port：v4 的产出只有一个通道（emit），目标版本与 digest 钉在任务上。

type ConfigAppliedFrame struct {
	Type string `json:"type"`
	// Revision 是本次生效的节点默认值 revision。
	Revision string `json:"revision"`
	// Hash 是 applied 文件内容的归一化哈希（中枢用它判 drift）。
	Hash string `json:"hash"`
	// MachineVars 是机器级生效值（含来源 local / node 的合并结果，不含值来源标记）。
	MachineVars map[string]string `json:"machineVars"`
}
    ConfigAppliedFrame 是节点合并落盘并生效后的回报。

    machineVars = 本机值 ⊕ 节点默认值。ns 默认值不在里面：它按任务所属 ns 解析、 随任务内存下发（config.md
    §2.4）。limits 也不在里面——中枢从 hello 的 localLimits + welcome 的 nodeLimits
    就能算出机器级预算，再传一份就是第三份真相。

type ConfigChangedFrame struct {
	Type string `json:"type"`
	// Revision 是新的节点默认值 revision。
	Revision string `json:"revision"`
}
    ConfigChangedFrame 是「这台的默认值变了」的提示，不带值也不带命令。

    节点丢了这条提示也不会漂移：下次 hello 会自己对齐。中枢不做「下推配置」。

type ConfigGetFrame struct {
	Type string `json:"type"`
	// AppliedRevision 是本机当前生效的 revision（空 = 还没有 applied 文件）。
	AppliedRevision string `json:"appliedRevision"`
	// AppliedHash 是本机当前 applied 文件的哈希（空 = 还没有 applied 文件）。
	AppliedHash string `json:"appliedHash"`

    ConfigGetFrame 让节点主动拉取当前节点默认值（D-I2）。

    请求带 appliedRevision / appliedHash：中枢可以据此回「你没变」的应答，也可以在 节点手改过 applied 文件（hash
    对不上）时把它拉回真相。应答是 WelcomeFrame。

type DeployRefs struct {
	// Namespace 是能力所属命名空间（中枢只能部署该节点被授权且明确指向的 ns）。
	Namespace string `json:"namespace"`
	// Name 是能力名（谱系，不是某个版本）。
	Name string `json:"name"`
	// Version 是解析到的版本号（省略 version 的能力由内容寻址分配）。
	Version int `json:"version"`
	// Digest 是部署身份（artifact.Digest，`sha256:<hex>`）：节点按它 GET 包体，
	// 拿到后必须自己重算并比对，不信任传输内容。
	Digest string `json:"digest"`
}
    DeployRefs 是部署意图/回执共享的身份四元组。

    四个顶层键（与父契约的字段表逐字对应），Go 侧只有一份定义，避免「两个帧各写 一遍 tag，改一处漏一处」。

type EmitRequest struct {
	To   string          `json:"to"`
	ID   string          `json:"id,omitempty"`
	Data json.RawMessage `json:"data,omitempty"`

type HelloCapability struct {
	// Name 是能力名（与 spec.metadata.name 同一套正则）。
	Name string `json:"name"`
	// Version / Digest 是这台机器上持有的那份（0 / "" = 未知或未部署）。
	Version int    `json:"version"`
	Digest  string `json:"digest"`
	// Commands 是 requires.commands 的逐条探测结果。
	Commands []HelloCommand `json:"commands"`
}
    HelloCapability 是 hello.capabilities[] 的一条：能力名 + 它的命令探测结果。

    为什么把「能力名」与「命令探测」放在同一条：中枢要回答的是 「这台机器能不能跑这个能力」，缺的往往是 requires.commands 里的一条命令；
    分开两条会让这个判断变成一次跨数组 join。

type HelloCommand struct {
	// Name 是命令名（requires.commands 的原样值）。
	Name string `json:"name"`
	// Found 是 LookPath 是否命中。
	Found bool `json:"found"`
	// Path 是命中的绝对路径（Found=false 时为空串）。
	Path string `json:"path"`
}
    HelloCommand 是一条命令探测结果：查到了给路径，没查到 Path 为空。

type HelloFrame struct {
	Type string `json:"type"`
	// Name 是节点名（集群内唯一；换名字 = 换一台机器）。
	Name string `json:"name"`
	// Token 是节点身份凭据（不绑 ns）。
	Token string `json:"token"`
	// Namespaces 是本机**申报**的 ns 列表（缺省 ["default"]，["*"] = 全部）。
	// 生效 = 申报 ∩ 中枢授权（welcome.namespaces）；它不是配置，不走 revision。
	Namespaces []string `json:"namespaces"`
	// LocalVars 是 anode.yaml 里的本机值（跨 ns 共用，同键压住节点默认值）。
	LocalVars map[string]string `json:"localVars"`
	// LocalLimits 是本机并发预算（逐叶覆盖节点默认值）。
	LocalLimits Limits `json:"localLimits"`
	// AppliedRevision 是 anode.applied.yaml 里的机器级配置 revision。
	AppliedRevision string `json:"appliedRevision"`
	// AppliedHash 是 applied 文件的归一化哈希（中枢据此判定 drift）。
	AppliedHash string `json:"appliedHash"`
	// AgentVersion / AgentCommit 是节点自报的版本事实（D-I13；空串 = 未知）。
	// 它们不进 digest、不进配置 revision：只用于 NodesAvailable / Node.status / upgrade。
	AgentVersion string `json:"agentVersion"`
	AgentCommit  string `json:"agentCommit"`
	// Facts 是节点内置事实（anode.md §3.6）：能力用 status.* 引用它们，
	// 中枢用它回答 Node.status 与「这台机器能不能跑」。它们只走 hello/welcome，
	// 不新增帧、也不参与节点匹配的配置 revision。
	Facts NodeFacts `json:"facts"`
	// Capabilities 是本机的能力探测结果（D-I13）：每条带 requires.commands 的
	// 命中情况（LookPath 结果）与可执行能力名。中枢据此回答 NodesAvailable
	// 的 CommandMissing，不需要再问节点。
	Capabilities []HelloCapability `json:"capabilities"`
	// Instances 是本机申报的并发槽位（slot / concurrency / busy，D-I13）。
	// 槽位事实只在 hello 上报；派发授槽仍由中枢的 lease 协议决定。
	Instances []HelloInstance `json:"instances"`
}
    HelloFrame 是节点连上后的第一帧（config.md §4.2 / anode.md §3.3）。

    它同时是「注册」「上报」「拉默认值」三件事，因为中枢从不主动问节点：一次握手 就把状态对齐，重连即全量重报。帧里**不带
    namespace**：节点令牌是集群身份， 不绑 ns；带的是 namespaces（本机申报列表），与中枢授权取交集生效。

type HelloInstance struct {
	// Slot 是 0..N-1 的槽位号。
	Slot int `json:"slot"`
	// Concurrency 是这个实例能同时跑几份。

	// Busy 表示当前是否有任务占着这个槽位。
	Busy bool `json:"busy"`
}
    HelloInstance 是 hello.instances[] 的一条并发槽位申报。

type LeaseAckFrame struct {

    LeaseAckFrame 是中枢对续租的确认：节点以「最后一次 ACK + 本地 deadline」判定 失联，到期自行 TERM，5s 后 KILL

type LeaseGrantFrame struct {
	Type    string `json:"type"`
	TaskID  string `json:"taskId"`

	LeaseID string `json:"leaseId"`

type Limits struct {
	// Total 这台机器同时最多跑几个任务（缺省 1，config.md §4.1）。
	Total int `json:"total"`
	// PerCapability 按能力名收紧；键是能力名或 "*"（未单列的能力）。
	PerCapability map[string]int `json:"perCapability,omitempty"`
}
    Limits 是节点的并发预算（anode.md §2 / config.md §4.1）。

    多维但本期只有两个维度：total（这台机器同时最多跑几个任务）与 perCapability （按能力收紧；"*" =
    未单列的能力）。有效并发 = min(空闲槽位, perCapability[NAME] ?? "*" ?? ∞, 能力的
    spec.concurrency.maxPerNode)——节点只能收紧，不能突破能力 自己声明的预算（capability.md §2.3）。

    只有本机 + 节点默认两层，没有 ns 级配额；逐叶合并（本机同名键覆盖 node，未写 继承）。它出现在三个地方：hello.localLimits
    / welcome.nodeLimits / applied 文件。

type LogsRequestFrame struct {
	Type      string `json:"type"`
	TaskID    string `json:"taskId"`
	RequestID string `json:"requestId"`
	// Attempt 是可选的目标 attempt（整数 ≥1）。省略（0）= 该逻辑 task 最近一次
	// 有档案的 attempt。跨节点重试时中枢必须按 attempt 的历史节点发请求，不能
	// 拿当前节点的日志冒充另一次执行。
	Attempt int `json:"attempt,omitempty"`
}
    LogsRequestFrame 让节点回报某条任务的日志尾巴。

    帧里只有「问的是哪条任务的哪一次请求」：任务入参（params）属于内部输入快照， 不该为了让一次排障取日志而把可能敏感的入参搬过网络。

    requestId 由中枢生成（同一条连接上可能同时有多条请求在飞），节点原样回带， 中枢只做字符串相等比较——「A 的日志被安到 B
    头上」这种错会静默发生，必须靠配对。

type LogsResponseFrame struct {
	Type      string `json:"type"`
	TaskID    string `json:"taskId"`
	RequestID string `json:"requestId"`
	// Attempt 是**实际**读到的 attempt：成功时必填（≥1），错误/无档案时为空。
	// 错误响应不能伪造一个 latest 冒充请求的历史 attempt。
	Attempt   int    `json:"attempt,omitempty"`
	Stdout    string `json:"stdout"`
	Stderr    string `json:"stderr"`
	Truncated bool   `json:"truncated"`
	Bytes     int64  `json:"bytes"`
	Error     string `json:"error,omitempty"`
}
    LogsResponseFrame 是节点对一次 logs_request 的回答。

    三条纪律：
      - 配对靠 requestId：中枢看不到的 requestId 一律丢弃（晚到的回包、过期请求）。
      - error 非空 = 没取到（目前只有 LogsErrNoLocalArchive）；空 error + 两个空串是
        「这次执行什么都没打印」，两者语义不同，不能合并。
      - 编码后 ≤ LogsResponseMaxBytes：truncated=true 表示档案里还有更多（档案本身 完整，被截的是这次回包）。

type TaskCancelFrame struct {

type TaskDispatchFrame struct {
	Type string `json:"type"`
	// TaskID 是逻辑任务 id（一个逻辑 task 一行，attempt 是计数器）。
	TaskID string `json:"taskId"`
	// AssignmentID 是本次派发的关联 id（诊断用，不是执行授权）。
	AssignmentID string `json:"assignmentId"`
	// ProposedAttempt 是拟定的 attempt 序号（grant 生效时才算数）。
	ProposedAttempt int `json:"proposedAttempt"`
	// Namespace 是任务所属 ns（决定 ns 默认值与授权判定）。
	Namespace string `json:"namespace"`
	// Capability 是钉住的目标版本与 digest。
	Capability CapabilityRef `json:"capability"`

	Params json.RawMessage `json:"params,omitempty"`

	NamespaceVars map[string]string `json:"namespaceVars"`
	// NamespaceVarsRevision 是这组 ns 默认值的版本。
	NamespaceVarsRevision string `json:"namespaceVarsRevision"`

    节点先校验 digest 与 `configRevision == applied`，再决定 accept /
    reject。 namespaceVars 是本任务所属 ns 的默认值（只含被引用的名字），随任务内存下发， 不落盘、不进

type TaskEmitAckFrame struct {
	Type string `json:"type"`
	// RequestID 必须与对应 task.emit 的 requestId 相同；节点据此找 waiter。
	RequestID string `json:"requestId"`
	// TaskID / Attempt 是回执的关联身份，节点必须核对后才会把结论交给原 HTTP 请求。
	TaskID  string `json:"taskId"`
	Attempt int    `json:"attempt"`
	// HTTPStatus 是这次结论在本地 emit 网关上的 HTTP 状态码（200/400/401/409/500）。
	HTTPStatus int `json:"httpStatus"`
	// Response 仅成功（含剪枝）时出现；与 Error 互斥。
	Response *EmitResponse `json:"response,omitempty"`
	// Error 仅失败时出现；与 Response 互斥。
	Error *EmitError `json:"error,omitempty"`
}
    TaskEmitAckFrame 是中枢对一次 task.emit 的结论。

    字段表（父批准）：type, requestId, taskId, attempt, httpStatus, response?, error?

    response 与 error 严格互斥——成功只 response（200，含剪枝回执），错误只 error （httpStatus 与
    EmitHTTPStatus(error.Error) 一致）。没有 attemptToken/leaseId/ namespace，也没有业务
    seq：迟到或不匹配的 ack 由节点网关按 requestId + taskId + attempt 丢弃（属于 N2 网关，不在本包）。

func (f *TaskEmitAckFrame) Validate() error
    Validate 检查 ack 的互斥与状态对应。

      - response / error 恰好出现一个；
      - 成功（response）的 httpStatus 必须是 200（剪枝也是 200，不是 4xx）；
      - 错误（error）的 httpStatus 必须等于 EmitHTTPStatus(error.Error)，且错误码 属于 EmitError
        文档化的封闭集合（未知码不当作可信 ack——那应该走传输层 的「结果未知」，不能伪造一个业务结论）。

    它不要求 Response/Error 的内部字段（taskId/eventId/pruned）：那些是 HTTP DTO 的既有形状，由 T1
    的同一份解释决定，本包不复制第二套校验。

type TaskEmitFrame struct {
	Type string `json:"type"`
	// RequestID 关联本次 RPC 与 ack；节点为每次 HTTP emit 生成新的，不持久化。
	RequestID string `json:"requestId"`
	// TaskID / Attempt / LeaseID / AttemptToken 是中枢做当前授权校验的身份四元组：
	// 旧 attempt / 过期租约 / 旧令牌一律拒绝，不因业务 id 已存在而绕过。
	TaskID       string `json:"taskId"`
	Attempt      int    `json:"attempt"`
	LeaseID      string `json:"leaseId"`
	AttemptToken string `json:"attemptToken"`
	// EmitRequest 匿名嵌入 → to/id/data 平铺在顶层，与 HTTP 请求同解释。
	EmitRequest
}
    TaskEmitFrame 把本地 emit 请求原样转给中枢。

    字段表（父批准，顺序即文档顺序）：

        type, requestId, taskId, attempt, leaseId, attemptToken, to, id?, data?

    `to`/`id`/`data` 的语义**逐字等于** HTTP EmitRequest（见 emit.go）：
      - to 缺省 = 本地/中枢按 missing_target 400 处理，**不是**帧错误：本帧的 Validate 故意不要求 to，否则
        Decode 阶段就把它判成坏帧，中枢再也没机会 回 HTTP 语义的 400/CLI 2。
      - data 省略 = 空对象语义；给了就必须是 JSON **对象**。数组/标量/字符串/null 是参数错误（param_type 剪枝或本地
        400），不能被默默当成"另一个对象"接受。
      - id 是唯一的业务幂等键（同 task 内生效），requestId 不是。

func (f *TaskEmitFrame) Validate() error
    Validate 检查 task.emit 的必填关联身份与 data 形状。

    **不要求 to**：缺 to 必须继续走到中枢的 HTTP 语义（missing_target → 400 / CLI 2），
    在这里拒绝等于把可回答的请求变成断连。也不校验 to 是否在本能力 next 里——那是 中枢权威（target_not_declared）。

type TaskPhase string

func (p TaskPhase) Terminal() bool
    Terminal 报告相位是否是终态（终态才起 taskTtlSec 计时）。

func (p TaskPhase) Valid() bool
    Valid 报告相位是否是封闭集合里的值。
